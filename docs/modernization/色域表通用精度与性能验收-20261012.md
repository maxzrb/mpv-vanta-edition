# 色域表通用精度与性能验收（2026-10-12）

后续配置调整：本报告记录本日 19:45 的验收。随后色彩管线拆为标准／HQ 两档，首次默认标准；本文的加密表与数值结论保留在 HQ 高色准模式，8 组实际颜色向量复测完全相同。当前入口及回退方式见[标准与 HQ 色彩模式](标准与HQ色彩模式-20261012.md)。

默认色域表已从 `48×32×256` 加密到 `96×64×256`。保持原三线性插值、FP32 运算／FP16 主纹理、色调算法、D3D11 和 HQ。四类映射的最大近似色差下降，稳态融合渲染阶段平均增加最多约 3.15 微秒。核心和线程策略未改。

## 2. 广覆盖精度测试

每个夹具包含 1,646 个颜色：257 级灰阶、84 个近中性色、576 个 HSV 网格点、729 个 RGB 网格点。图像为 768×560，每块16×16；源是无损 FFV1 全范围 YUV444P16，先验证 FFmpeg 解码与原始整数逐字节相同，再验证实际 GPU 三源平面的整图整数样本。最终 RGB10 读回取各块中心 8×8 像素均值，纳入默认抖动。

分别对广色域 SDR、HLG、PQ 和显式 ICC 测试默认、中间、加密三档，覆盖 D3D11／Vulkan，共24组。生产配置修改后，又去掉尺寸命令行覆盖，复测四类／双后端8组，确认实际生效值为96／64／256。

以下 ΔE00 是**实际输出与所选映射连续 float64 公式之间的近似误差**。SDR／HDR→SDR 的映射会按目标色域和亮度重分配颜色，指标描述执行精度。测试固定目标白80 nit、黑位0，ICC为配置文件实际XYZ矩阵与gamma2曲线。

| 路线 | 原表最大 ΔE00 | 加密表最大 ΔE00（双后端最大） | 加密表 P99（双后端最大） |
|---|---:|---:|---:|
| BT.2020 SDR→经典SDR | 1.24244 | 0.71412 | 0.32768 |
| HLG→经典SDR | 0.84763 | 0.33294 | 0.17945 |
| PQ→经典SDR | 0.67913 | 0.41992 | 0.19132 |
| BT.2020 SDR→ICC gamma2 | 1.19043 | 0.72660 | 0.32495 |

所有灰阶均单调。逐色点对照的最大局部误差增加为0.15506 ΔE00，未出现超过0.25的增加；加密表不会让每个色点的误差都下降。中间档64／48／256在SDR中有两个色点增加超过0.25，未选为默认。三次插值曾出现中性偏色，本次保留三线性插值。

SDR、HLG、PQ 的离散表／表示步骤模型最大编码残差分别约0.00170、0.00189、0.00310，均小于项目0.004门槛。ICC的内部黑点近似和17阶四面体插值另有残差，解析ICC参考按其实际物理XYZ和TRC计算：这层最大残差0.12683 ΔE00，小于项目0.25门槛；编码残差最高0.004068仍保留在记录中。此项没有逐节点复现内部ICC表。

ΔE00实现以 [Sharma／Wu／Dalal公开测试资料](https://hajim.rochester.edu/ece/sites/gsharma/ciede2000/) 的34对数据及对称性验算，最大误差4.94990×10⁻⁵，符合资料四位小数精度。门槛是本项目的软件验收规则。

## 3. 参考模型补全

HLG经典SDR先按1000 nit源执行逆OETF和加权亮度OOTF，再执行默认母版峰值软折返、自适应色调映射及色域压缩。母版1000 nit可信时，95%膝点以上的软折返必须计入。它与ACM/scRGB的80 nit HLG目标适配分支不同。

峰值检测使用写回前源值；后续映射消费编码RGB的FP16向零写回值。连续参考保留原始源，离散／表示步骤参考单独计入这次量化。ICC参考读取文件中的S15.16原色XYZ列并作Bradford白点适配，保留矩阵舍入；把该文件假设成精确BT.709会在近零通道放大编码残差。

本轮早期漏项参考和短片循环性能结果保留于忽略的测试目录，最终汇总采用补全后的结果和长片测量。最终JSON的输入哈希明确列出采用的文件。

## 4. 动态HDR时序

两种后端分别逐帧验证31帧：500 nit稳定场景、510→600 nit渐变、回到500、突切4000、连续全黑、转入100及返回500。每帧由已知整数源独立计算峰值统计，再推导20帧周期IIR、一个统计单位以内去抖、活跃工作组比例和1%／3%场景滞回。

读回工具使用`frame-step`推进；仅序列前定位一次，不在帧间seek重置IIR。62次读回的GPU源整数整图一致，最终scRGB最大线性误差0.00077689，小于项目0.002门槛。亮场突切若误用上一帧峰值，误差为0.73950；实际同帧模型误差约0.00064，排除了这一帧延迟。编译Shader也验证FP32浮点及无浮点降精度标记。

## 5. 播放、缓存及资源代价

性能测试使用独立无读回插桩的播放器进程；固定16个解码线程，关闭解码性能脚本的自动参数改写，HQ和默认同步／呈现保持相同。每个片源、每种后端按原表／加密／加密／原表执行，分别包含冷缓存和磁盘热缓存。使用12秒测量窗口，4K60为24秒。`vo-passes.count`是采样环容量，非累计帧数；测量媒体推进扣除丢帧后覆盖最多256条计时环，并拒绝负计数或时钟重置。

片源含30秒FFV1网格、独立编码4K24 HEVC10（软件／硬件解码）、真实4K24 HLG、真实1080p24 VVC、真实4K60 HEVC。4K60原片只有20秒，测试副本流拷贝延长，原文件未改。

表内耗时是**色域映射所在的融合阶段**，包含该阶段的缩放／编码／抖动，不能当成独立色域映射计时。

| 场景 | D3D11融合阶段：原表→加密，ms | Vulkan融合阶段：原表→加密，ms |
|---|---:|---:|
| FFV1网格／HQ放大 | 0.84841→0.85156 | 0.26385→0.26617 |
| 4K24 HEVC10软解／缩小 | 0.41692→0.41762 | 0.33894→0.33967 |
| 4K24 HEVC10硬解／缩小 | 0.41702→0.41921 | 0.34030→0.33990 |
| 独立4K24 HLG软解 | 0.48874→0.48862 | 0.12236→0.12305 |

共48轮、672秒测量窗口。前40轮两变体的丢帧／解码丢帧／mistimed计数增量均为0。VVC和4K60这两条实际路线没有生成色域表；它们提供不启用该步骤时的负对照，CPU／丢帧波动不能归因为加密表。

4K60软解的24秒窗口：D3D11原表580／395，加密402／408；Vulkan原表353／321，加密400／358丢帧。结果没有一致改善，仍未原速同步零丢帧。未采用“某一轮少丢帧”作为通用提速证据。

每张表的逻辑资源3→12 MiB。实际冷生成常由约22～52 ms变为64～87 ms；有些起播会先后生成两张不同黑位的表。包含Shader编译、启动和五次fresh的冷就绪耗时也有波动，网格D3D11本次2.678→3.330秒。热缓存原表／加密表均命中，加密12 MiB并未被磁盘缓存拒绝；热就绪的最大正差约0.076秒。4K／HLG热启动进程私有提交量差约27～44 MiB，包含缓存及驱动资源，不能简化成唯一9 MiB额外内存。

4K24软件解码D3D11分段中，上传帧约1.94 ms，颜色解码约0.51 ms，垂直缩小约0.85～0.97 ms，最后水平缩小／色域／编码／抖动约0.42 ms。加密表所在阶段的增加不足0.001 ms，远小于上传和缩放。本轮留下了上传／解码相关进程CPU／渲染的分段证据；GPU上传计时不等于独占CPU上传耗时，不以硬解前后CPU差冒充精确解码耗时。
