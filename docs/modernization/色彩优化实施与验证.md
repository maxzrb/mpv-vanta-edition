# 色彩准确优化：实施与验证

> 历史记录：2026-10-06 的滤镜、色彩与性能行为已更新，当前实现见[最新结果报告](滤镜恢复与色彩性能优化结果-20261006.md)。

日期：2026-10-04。配置与软件回归已实施；HDR 面板色准、多 GPU 和完整动态格式验收仍未完成。项目版本仍为 v1.5.7，本轮没有打包、发布或修改《发布流程.md》。

## 已实现的行为

默认保留 gpu-next／D3D11、BT.709／sRGB 显示目标，不开启 Windows HDR、AI、Shader 调色或额外对比度恢复。`HDR2SDR` 的 `hdr-contrast-recovery` 从 0.30 改为 0，旧值保存在用户主动应用的 `HDR-Contrast-Optional` 配置组。亮度、矩阵、传递函数和位深不按显卡性能档位修改。

原一级菜单保留。「画面 > 色彩目标」使用统一 `color-target.lua`，包含 SDR sRGB、可信系统 ICC、能力检查后启用 HDR、恢复切换前目标、查看色彩状态。input.conf 是三种菜单的共同入口；原有着色器与视频滤镜分类保持。

管理器保存进入前的 ICC、目标原色／曲线／峰值／对比度、输出格式与色彩空间、参考白、输出提示等选项。恢复只覆盖仍与本系统最后写入值相同的项目，保留用户后续主动修改。取消和切片令旧验证回调失效；显示 UID、系统 HDR 状态或亮度报告变化后重新检查。失败不删除第三方滤镜，也不改变视频同步策略。

HDR 入口要求 Windows HDR 已开启、显示器明确支持 HDR、可信峰值大于 203 nits、D3D11 和可定位的输入流。峰值默认取系统／驱动报告；可在 `script-opts/color-target.conf` 指定测量值，状态页区分来源。未知黑位不推断无限对比度；超界驱动对比度报告不强写。没有显示检测插件时普通播放正常，HDR 能力显示未知并阻止启用。

首选候选为 FP16 线性 scRGB：请求 rgba16f／linear，验证实际 `video-target-params` 的 rgba16hf、scRGB 与 BT.709 容器。超时尝试 PQ／rgb10a2 兼容输出，再失败回到明确 SDR 映射。每次验证有超时上限，不持续轮询。成功状态仍标「HDR 实机色准待测」。scRGB 容器不能等同于 SDR 色域，负值及超范围值的实际保存仍需线性回读验证。

本机证实改变 D3D11 输出选项会重建 VO。逐项直接写入曾造成瞬时不支持的格式组合和 HEVC 参考帧错误，已改为有界事务：保留暂停状态，暂时撤下视频轨，完成目标写入后恢复原轨和暂停状态。音轨、字幕选择不改；不可定位流拒绝进入 HDR 重建路线。切换可能有短暂视频中断，不承诺无缝。真实远程 HDR 流、多音轨和 HDR 硬解重建仍需额外覆盖。

旧 `hdr-mode.lua` 默认 `noth`，不安装自动切换观察器。手动开启其 pass／switch 时按 PQ／HLG／DV 源状态判断，色彩目标交给新管理器。系统 HDR 切换等待最多 10 秒；超时／切片恢复播放。脚本退出仅恢复自己改动前的系统 HDR 状态，不强制关闭原本开启的桌面。用户手动选色彩目标后优先保留手动选择。

8k-fix 仍采用 auto-safe 硬解，但删除强制 `video-sync=audio`，用户选定的同步方式不再被片源分辨率覆盖。该修改不能补足 RX 6600 对特定 8K AV1 HDR60 素材的吞吐缺口，见 [掉帧报告](8K-AV1掉帧排查.md)。

## 信息与精度的边界

状态页分别显示解码源、含推断的有效输入、滤镜输出、实际渲染目标、ICC、系统 HDR、显示链接报告位深、峰值来源和参考白请求。当前没有可读的完整交换链属性，明确显示未知；实际交换链格式需要日志证据。处理中间纹理由 libplacebo 选择，不把 F16 存储称为全程 16bit 运算，也不把显示链接位深称为面板实测。

HDR 参考白采用 auto，由本机核心查询系统；失败回退 203 nits。状态页显示的是请求／策略，未冒充已取得的实际查询值。DV／动态 HDR 的格式识别与重整形、RPU、FEL、动态映射执行分开，无法从属性确认的执行状态标未知。ICC 自动入口仅适用于匹配当前显示器和模式的可信系统描述文件；启用不证明该 ICC 存在或已校准，Windows ACM／HDR 校色应独立核查，避免重复转换。

3FP 可借鉴能力判断、scRGB 亮度标尺与回退设计；“色彩 T0”没有成为配置依据。其固定版本源码、用户 EXE 静态核查和 HLG 差异见 [3FP 核查](3FP与mpv色彩精度核查.md)。不能据这些软件实验断言 mpv 或 3FP 的 HDR 色准排名。

## 本机验证结果

环境：Windows 11、RX 6600、ASUS VG249Q1A，1920×1080／165Hz，SDR sRGB 模式；显示链接报告 8bit，非面板测量。核心 shinchiro 20261004，mpv v0.41.0-1095-g413ff0b1c、FFmpeg N-127165-g12c589a37、libplacebo v7.374.0。

| 检查 | 方法与结果 | 证明范围 |
|---|---|---|
| 语法与配置 | 132 Lua、28 Python，引用及用户既有选项检查通过 | 软件语法／配置完整性 |
| 状态机 | 未知能力、不可定位流、设置失败、FP16→PQ→SDR、跨屏、切片旧回调、恢复所有权、状态提示保持通过 | 故障注入；不是实际硬件拒绝交换链 |
| 旧 HDR 生命周期 | 默认关闭、源识别、暂停超时、取消、原系统状态恢复通过 | Lua 故障回归 |
| 五类编码素材 | SDR8、SDR10、BT.2020 SDR、HDR10、HLG；完整配置 SDR／ICC／恢复切换、源标记保持、SDR 桌面 HDR 门禁通过 | 合成素材实际解码；软解、静音；不是五类色准测量 |
| 模拟 HDR 能力 | 隔离配置注入能力：实际 rgba16hf／scRGB 目标，再关闭能力回退 SDR；最终日志无 GPU／解码错误 | 本机输出协商和恢复；系统实际仍为 SDR |
| 高位深灰阶 | RGB16 sRGB PNG，1024 个灰阶及色块；GPU 16bit PNG 截图最大采样码值误差 0、保留 1024 级 | GPU 截图出口未退化为 8bit；不是中间纹理或屏幕精度 |
| 范围端点 | 已先解码核查无损夹具：Y=0／64／940／1023；limited 截图 0／0／65534／65535，full 为 50／4150／60268／65535 | 10bit 范围端点与全范围中间值不误裁剪；非完整传递函数标定 |
| 数学参考 | PQ 往返、scRGB nits/80 与 FP16 存储量化、HLG 亮度加权 OOTF、BT.2020 红→709 负通道向量通过 | 数学复算，不代表 GPU 执行与模型完全一致 |
| 普通播放兼容 | HEVC10 硬解、音频、双字幕、网络文件及原增强菜单回归通过 | 普通播放功能；不代表 HDR 重建硬解全面通过 |

软件检查使用 `tools/test-color-state.lua`、`test-hdr-lifecycle.lua`、`validate-color-target.py`、`validate-color-ramp.py`、`validate-color-range.py`、`color-reference.py`。现有 `check-modernization.py`、`validate-modernization.py`、`validate-quality-menu.py`、`test-playback-compat.py` 一并回归。夹具与原始结果位于忽略的 `tmp/modernization/`；公开证据摘要见 [色彩结果](color-validation-results.json)。包含个人播放历史的完整日志不发布。

## 升级与回退

组件锁增加本地色彩管理策略及许可说明，定制脚本不能被上游整文件覆盖。修改前快照为 `backup/color-accuracy-20261004-203559/`，新旧配置校验值见 [色彩升级清单](color-upgrade-manifest.json)，具体操作见 [升级和回退](升级和回退.md)。核心及其 FFmpeg／libplacebo 未在此色彩阶段再次替换；以后升级须重跑上述软件回归，HDR 结果按设备重新确认。
