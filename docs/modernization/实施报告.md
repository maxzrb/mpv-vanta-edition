# 播放与画质现代化实施报告

> 历史记录：2026-10-06 的滤镜、色彩与性能行为已更新，当前实现见[最新结果报告](滤镜恢复与色彩性能优化结果-20261006.md)。

实施日期：2026-10-04。环境：Windows 11 x64、RX 6600、SDR 显示器 sRGB 模式。代码与本地组件已更新，项目版本仍为 v1.5.7，未打包或发布。

## 实施结果

弹幕程序、专属选项、菜单、快捷键与维护者审计源已移除，共享字幕依赖保留。安装器源码增加可回退的旧组件隔离，不删除用户下载和历史备份。开发历史备份保留，检索到其中的旧弹幕文字不代表有效入口。

新增 `quality.lua` 统一增强入口，区分未安装、硬件不支持、准备中、准备后可用与失败重试。后台进程带取消、超时与代际检查，切片／取消后的旧回调失效。实际推理前校验整套文件，请求真实帧，并检查位深与矩阵／原色／传递函数／范围属性；不会因为 DLL 存在就判为可用。

AI 默认关闭，推荐 RIFE 更新到现存的 4.25 Lite 模型。原分辨率路径移除 720p／1440p 隐式缩放，性能模式显式注明 720p。只清理自身三个滤镜标签及自身 Shader 路径；外部滤镜和 Shader 保留。轻量混合帧插值默认关闭，手动启用时配置所需播放同步，关闭时恢复原值。

统计面板改用 Windows 系统时间和 PDH GPU Engine，按物理引擎汇总并按 LUID 标识；数据表示整机占用，不冒充 mpv 进程占用。关闭后停止采样、取消兼容查询，查询不重叠，文件切换使旧结果失效。独立覆盖层与文本缓存避免不必要更新，动态页面限频，原生采样每 2 秒，兼容查询最多每 10 秒；没有数据时显示不可用／采样中。

已审阅杳知 1.0.6-2 发行包内统计源码与 MIT 许可。参考其减少重绘和轮询的思路，本轮原生指标模块独立实现，未复制其监控代码，也未引入直播功能。统计覆盖层的字体尺度已做截图复核并修正。

追加跟进杳知起播徽标：素材 manifest v23 → v24，新增 DRA 的 24 张透明度／尺寸／白色样式素材，保留其 MIT 授权和署名。合并视频徽标不等待迟到音轨及几何就绪触发；保留本地真实格式优先、四种黑边检测策略，以及用户已有双路与白色样式选项。DRA 识别与徽标预览通过，实际 DRA 音频解码仍需对应素材。

## 色彩管理与 3FP

默认目标是 BT.709 原色、sRGB 传递函数、SDR 输出，不强制 scRGB／Windows HDR，禁用自动去色带、创意色域／对比度配置。保留 libplacebo 的 HDR→SDR tone mapping、色域映射和自动输出抖动。目标亮度 80 cd/m² 是当前配置／推断标尺，不是显示器实测亮度。

[3FP VideoRenderer.cpp](https://github.com/Lake1059/FFF_Project/blob/master/FFF.Native/3FP/Render/VideoRenderer.cpp) 的 `WantsScRgbPresentationPath` 在 HDR／广色域时请求 scRGB；高位深 SDR 还取决于 SDR scRGB 策略，不是所有 10bit 都无条件走 FP16。其 FP16 交换链与线性 scRGB 标尺、能力协商及失败回退值得参考。mpv 本身已有图形输出能力检查，本轮沿用原生协商，未搬入另一套 Windows 渲染器，也未复制 3FP 代码。

本机日志分别观察到源 8／10bit、HDR 渲染中间纹理 `rgba16hf`、交换链 `R10G10B10A2_UNORM`、SDR 色彩空间 `RGB_FULL_G22_NONE_P709`，不能把这些统称「16bit 输出」。mpv 状态属性显示目标 rgb10a2／sRGB；运行时 `display-swapchain` 属性不可用，状态页明确未知。驱动报告的显示器 8bit 与面板实际精度／色准也应分开，后者需测量。「T0」排名没有纳入技术判据。

状态页显示原始解码信息、有效输入（可能包含推断）、滤镜输出、目标、亮度标尺与 ICC 状态。没有元数据时不把推断包装成已知源值。sRGB 模式与系统 ICC／Windows ACM 是否重复转换需要依实际显示环境决定，不自动叠加。

统计对比使用同一新核心、同一 1280×720 24fps 固定合成画面，每种关闭／首次打开／反复开关／持续显示各重复 3 次，每次 6 秒。只加载各自 stats，禁用内置 stats；原生统计与兼容回退生命周期分开测试。mpv CPU 由进程时间归一到整机逻辑 CPU，GPU 是整机 PDH，渲染耗时来自 `vo-passes`。数值和逐次结果见 [统计测试数据](stats-results.json)。

双方均未新增掉帧、延迟帧或错时帧。新版所有场景外部查询为 0；最终旧版持续显示三轮分别为 18／22／18 次。可确认轮询进程消除，短片段 CPU／GPU／渲染耗时波动不能证明长期整体降耗。新版文字尺度修正也包含在测量中；测试不包括旧版子进程自身 CPU，持续播放和高负载长时段验收仍应追加。
