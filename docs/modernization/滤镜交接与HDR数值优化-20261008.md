# 滤镜交接与 HDR 数值优化（2026-10-08）

本轮延续已批准的色彩、性能和健壮性优化。项目版本仍为 v1.5.7，保留既有修改和个人设置；未提交、打包或发布。

## 已应用的修复

1. **色彩状态去重。** `video-target-params` 可逐帧通知相同内容，像素比例 `par` 的未知值可能为 NaN。NaN 不等于自身，导致普通比较失效；显示信息的 JSON 键序也不适合作为变化依据。改为原生字段比较，两个未知 NaN 视为同一状态，目标未变时不再重读所有设置或重复广播；真实目标、亮度、显示身份和外部覆盖变化仍更新。短诊断中状态写入由数百次降至 3 次；这个次数比较不是固定性能收益百分比。
2. **同帧率滤镜完成状态。** CCD 等滤镜已初始化、开始输出，却可能没有再次触发帧率变化或 `playback-restart`，因而卡在“启用中”。现在同时监听真实 `video-reconfig`，在初始化成功且没有错误时转为“已添加”。保留原错误回退和旧请求失效机制，不增加模拟试跑。
3. **精度信息更明确。** 详情区分 NV12／P010 等整数有效位深与 FP16 浮点存储，显示实际可观察的 GPU 表面、copy 或 VS 下载交接。最终 FP16 输出不代表所有模型、VS 或中间纹理都为 FP16；当前会话未逐阶段采集时明确注明。简洁启用列表仍保持简短，播放性能入口仍位于“其它”。
4. **组件更新后补丁可恢复。** K7 手动维护工具增加隔离测试入口，模拟已知上游文件重新覆盖后重用现有七文件补丁，验证默认只读、备份、幂等、保留其它本地补丁，以及未知文件在写入前全量拒绝。它只供维护者手动执行；新上游版本须适配补丁上下文与哈希，不能宣称自动兼容未知版本。

普通播放、菜单及滤镜选择继续不调用组件扫描、显卡名称核查、整包校验或准备认证。没有新增解锁、二次开启或自动降画质。

## HDR 独立数值参考

此前的 HDR 增强一致性和模拟输出协商之外，本次增加独立 GPU 转换参考：受控有限范围 YUV44416 BT.2020 NCL 色块分别带 PQ／HLG 标记，独立计算源量化、传递函数及 BT.2020→709 的线性亮度结果，覆盖黑位、暗部、203 nits、亮色、负 RGB 与超过 scRGB 1 的值。HLG 使用 1000 nits／零黑位参考 OOTF。

测试在无用户配置、GPU D3D11、显式线性 scRGB 目标下隔离转换；禁用动态峰值分析、对比度恢复、逆映射、去色带及抖动等额外因素。先用常量 Shader 校验读回标尺，再分别编码正值和负值，通过 16bit PNG 读取并重建线性亮度，避免大偏移吞掉暗部精度。源压缩夹具与原始 YUV 字节一致。

| 参考 | 最大绝对通道亮度误差 | 结果 |
|---|---:|---|
| PQ | 0.539 cd/m² | 通过 |
| HLG | 0.610 cd/m² | 通过 |

逐通道阈值固定为 `0.10 + 0.002 × abs(参考亮度)` cd/m²，涵盖 GPU 工作纹理和仪器化整数读回误差；不是所有亮度都允许 0.610 的统一阈值。结果不代表原始 FP16 纹理读取、默认动态色调映射的全部算法、增强模型全链路或物理面板测量。没有修改 Windows HDR 开关，没有强制改变模型兼容位深。

## 滤镜交接、性能及资源观察

环境为 Windows 11／RX 6600／165Hz SDR 桌面，完整配置隔离副本、1920×1080窗口、正常GPU表面复制，WASAPI静音。相同视频串行比较直接 D3D11VA 与 copy，增强预热5秒后采样至少20秒、重复三轮并交替顺序；有效采样期间没有并行启动其它维护测试播放器。2轮与菜单维护测试区间重叠已排除并串行重测；旧配置、最小化或短诊断不混入最终结果。

CPU 是 mpv 进程占一个逻辑核心的百分比，不是整机总占用或 GPU 功耗。SVP／CCD 性能夹具没有音轨，因此“零音频欠载”不适用；实际音频与组合另作下述 AV 回归。RIFE 的六轮稳态20秒均无音频欠载，加载与重新初始化阶段每轮仍观察到4个实际音频欠载事件（重复日志不重复计数），保留为加载停顿限制，未计成稳态问题，也没有隐去。

18组进程均完成三次启停、暂停与精确跳转，合计54次；关闭后滤镜列表与活动项清空、原解码后端、GPU／copy交接格式及源尺寸恢复，5秒回归时钟比范围为0.9919～1.0051，无显示／解码掉帧。所有18份日志的色彩状态写入为2～4次，没有恢复逐帧广播。5秒关闭后观察只是状态兼容回归，不作为20秒性能排名。

没有修改默认：SVP 的copy CPU中位数较低，但三轮并非一致胜出且波动较大；RIFE两条路线都实时、CPU差异有限；CCD全分辨率4K两条路线都不实时，不能把慢速媒体推进当低功耗收益。继续使用普通播放auto-safe、已有CPU滤镜起播兼容路径、运行中VS按核心协商下载、手动指定后端不覆盖；不自动降分辨率，不加入新的滤镜前核查。
