# 解码器安全切换与多编码回归（2026-11-01）

## 结论

解码器不能在活动视频的 GOP 中间直接修改 `hwdec`。该操作会重建当前解码器，但已经送来的依赖帧没有对应参考画面。HEVC 会报告 `Could not find ref with POC` 和 `Error constructing the frame RPS`；同类风险不只存在于 HEVC。

本轮在 `decode-performance.lua` 中加入统一安全重建事务：保存播放位置、暂停状态、视频／音频／主副字幕选择和运行中加载的外挂轨，重载当前播放列表项，再用文件局部选项设置新解码方式并从保存位置重新定位。快速连续切换会串行排队；不可定位的直播流不会中途破坏当前解码器，新选择保留到下一个可定位文件生效。

## 根因

- 旧菜单和快捷键直接执行 `mp.set_property('hwdec', ...)`。
- mpv 随即重建 FFmpeg 解码器，但硬件解码器仍会收到当前码流中依赖旧参考帧的 HEVC NAL。
- 日志中的新解码器虽然进入“等待关键帧”状态，实际仍可能在关键帧前处理依赖帧，形成参考帧错误和后续画面跳过。
- 原问题不是单纯“首帧前操作过早”。一次切换发生在已显示画面后，仍可复现。

## 旧直切对照

使用完整配置、`no -> d3d11va-copy`、起播窗口中切换，每种编码各三轮，并重复多组独立运行。错误出现存在竞态，并非每轮必然复现；下表为多组运行的观测范围。

| 编码 | 单次尝试错误行数范围 | 是否至少复现一次 |
|---|---:|---|
| HEVC 10-bit 生成片 | 0～228 | 是 |
| H.264 8-bit 生成片 | 0～1 | 是 |
| AV1 10-bit 生成片 | 0～3 | 是 |
| VP9 10-bit 生成片 | 0～3 | 是 |
| HEVC 10-bit 既有失败样片 | 0～402 | 是 |

最近一轮三轮结果：HEVC `0/228/0`，H.264 `0/1/1`，AV1 `0/3/3`，VP9 `0/0/0`，既有 HEVC 样片 `0/399/0`。该轮 VP9 未复现，不代表以前各组都安全；前几组独立运行曾稳定出现 `0/3/3` 或 `3/3/3`。

- `hevc: Error constructing the frame RPS.`

## 安全路径回归

安全路径在 HEVC、H.264、AV1、VP9 上完成硬件到软件、软件到自动硬件切换；暂停位置误差为 0 秒。HEVC 另测播放中切换，恢复后继续推进。外挂字幕选择和播放列表当前项保留。

| 编码 | 初始实际解码 | 安全切换次数 | 位置恢复 | 目标错误 |
|---|---|---:|---|---|
| HEVC | `d3d11va` | 3 | 4.208→4.208；播放中 4.375→4.458 | 无 |
| H.264 | `d3d11va` | 2 | 4.208→4.208 | 无 |
| AV1 | `d3d11va` | 2 | 4.208→4.208 | 无 |

## 边界

- 本机实际验证的是 D3D11VA 直出、D3D11VA copy 与软件解码。NVDEC、QSV、AMF、CUDA 等缺少对应硬件／驱动时无法做实际解码认证，但菜单切换共用同一重载事务。
- 安全重建不是无缝切换。它会重新打开当前文件并从安全位置定位，因此会有短暂停顿；这是避免参考帧损坏的必要代价。
- 不可定位流无法安全重建当前解码器，菜单选择会保留到下次打开可定位文件。当前流不会被破坏性切换。
- 本次只修改脚本和测试，没有重建或上传本地 v1.6.5 候选包。现有候选归档仍是修复前产物。

## 后续：重载异常收尾与关键帧偏好（2026-11-01）

前述“尚未重打包”为16:54时点的历史状态；17:18已完成主体修复的本地重打包。本轮用户再次授权补齐异常收尾并重打1.6.5，仍暂不上传，最终归档结果以本轮构建报告和版本记录为准。

代码复核发现：重载命令已经提交、但在`on_loaded`前失败或被取消时，旧实现未释放`reload_state.active`，空闲后的后续菜单选择仍会排队。Lua模拟已复现；新增真实mpv加载钩子分别注入缺失输入、停止和替换文件，验证异常清理后可重新选择、打开和切换解码方式。正常重载同样会发送旧文件的`end-file/stop`，不能在该事件上无条件清理。

- 新事务记录是否已开始加载。忽略新加载前的正常旧文件卸载；新加载失败／停止、替换文件或回到空闲时清理事务与待应用参数。
- 排队回调校验请求序号、文件代次、路径和空闲状态，避免旧回调覆盖更新选择或作用于下一文件；取消事务不会擦除已保存的用户偏好。
- 实播额外发现：完整配置中`seek_mode=keyframes`会将普通`start`定位落到前一个关键帧。安全重载现在临时使用精确定位，在`playback-restart`或卸载／取消时还原原跳转策略，不改用户配置文件。
- 加载日志改为“解码器重载参数已应用”，不再将`on_loaded`当作首帧恢复完成；实播验收另等实际解码方式与定位结束。

新增`tools/test-decoder-reload-lifecycle.py`，使用完整配置隔离副本，固定关键帧偏好与单项播放列表，注入仅限测试进程的加载异常。预期的缺失输入错误只属于故障注入段，恢复后的新增日志不应有目标错误。Lua回归还覆盖旧文件卸载期间继续排队、无新加载即空闲、过期回调遇到新选择／停止／换片，以及精确定位偏好恢复。
