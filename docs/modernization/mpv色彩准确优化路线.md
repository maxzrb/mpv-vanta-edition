# mpv 色彩准确优化路线

日期：2026-10-04。适用 Windows 10/11、AMD／NVIDIA／Intel；当前核心为 shinchiro 20261004，gpu-next／D3D11、libplacebo v7.374.0。本路线的软件实现已写入活动配置并完成本机回归，HDR 面板与多 GPU 验收仍待外部设备。完成范围和证据见 [实施与验证](色彩优化实施与验证.md)。现有研究依据见 [3FP 与 mpv 核查](3FP与mpv色彩精度核查.md)。

## 目标与边界

准确播放优先保证解码、范围、矩阵、传递函数、色域与亮度标尺正确；再减少处理中间量化，最后验证 Windows、驱动及显示器输出。FP16 是承载方式，不是色准等级。HDR 为重点，包含 HDR10、HLG 与不同 Dolby Vision 路径，不能以 SDR 显示器上的播放成功代替 HDR 验收。

保留当前一级菜单；配置入口在「画面 > 色彩目标」，诊断在现有处理状态／工具入口，字幕亮度在字幕菜单。超分、补帧、调色与创意 LUT 由用户主动开启，不属于准确播放基线。默认不自动切换 Windows HDR。

## 实施前配置审计与优先级（历史基线）

| 项目 | 当前事实 | 实施要求 |
|---|---|---|
| SDR 默认 | Target 为 BT.709／sRGB、关闭 ICC 自动加载 | 保留为本机 sRGB 模式基线；实际面板曲线仍需测量 |
| 中间精度 | HDR 测试日志确认 rgba16hf | 保留 gpu-next；禁止用 fbo-format 宣称强制全程 FP32 |
| 输出标记 | Target 关闭 colorspace hint，显式请求 sRGB | 比较显式 sRGB 标记和当前路线，按协商结果验证，不盲目全局启用 HDR 标记 |
| 局部对比度 | 全局应用 HDR2SDR，hdr-contrast-recovery=0.30 | P0：准确基线改为 0；原数值仅保留用户可选观感方案 |
| HDR 菜单 | Color-HDR 使用 auto 目标和交换链 | P1：提供明确协商与失败状态；自动查询不足不宣称可用／直通 |
| 旧 HDR 脚本 | hdr_mode=noth；读取 target_contrast，而实际属性为 target-contrast | P0：修正属性名和恢复逻辑；默认关闭，避免与新目标管理器竞争 |
| 旧脚本判断 | 用 max-luma>203 判断 HDR；恢复 SDR 时写死 target-peak=203 | P0：按源 PQ／HLG／DV 状态判断，完整恢复进入前目标；亮度只作为附加信息 |
| ICC | Color-ICC 使用系统 ICC；另有通用参考 ICC+ | 明确当前显示器／模式匹配；参考色域 ICC 不等于本机校准文件 |
| 去色带 | HQ 明确 deband=no，DeBand-low 仅设置参数 | 保持默认关闭；不能仅因加载参数组就称自动启用了去色带 |
| 峰值分析 | auto 与现有百分位／衰减等固定参数 | 留作候选基线；对快进、场景切换与小面积高光单独验证，不称其唯一准确 |

## 第一步：建立可复现的准确播放基线

统一管理色彩目标涉及的选项：ICC、target-*、hdr-reference-white、colorspace hint／strict／mode、D3D11 输出格式／色彩空间、tone／gamut mapping 和 inverse-tone-mapping。记录进入模式前的完整状态；切换或失败时仅恢复本系统仍拥有的设置，保留用户之后的主动修改。重复选择幂等，切片／跨屏旧回调失效，配置写入过程避免观察器循环。

准确基线的 brightness／contrast／gamma／saturation／hue 为零；无创意 LUT、调色 Shader、AI、轻量插值与额外对比度恢复。明确分开“恢复色彩目标”与“清空增强”，不删除第三方滤镜。主配置原有个性化项继续保留；审计实际生效值，不能只看注释和配置组名称。

源信息分三层报告：解码帧实际标记、mpv 推断后的输入、滤镜输出。缺标记显示未知／推断来源，错误标记只允许用户针对当前文件修复，不全局强制 BT.709、有限范围或 10bit。加入全／有限范围端点、色度位置与高位深保留检查。

SDR 保留两条明确路线：显示器 sRGB 模式，以及匹配当前显示器／模式的可信 ICC。sRGB 分段曲线、gamma2.2 与 BT.1886 参考显示解释须用测试图比较；显示器菜单名为 sRGB 不证明实际曲线。当前 treat-srgb-as-power22=no 是明确候选，未测量前不宣称普遍最准确。

验收：首次启动、切片、重复点击、恢复与缺 ICC 均无错误目标；截图／GPU 回读和实际显示测试各自记录。完成后形成选项生效清单与回退快照。

## 第二步：实现 HDR 输出协商和亮度来源管理

### 按显示环境选择

| 环境 | 推荐路线 | 能力／失败处理 |
|---|---|---|
| Windows HDR 关闭、SDR sRGB | 当前 SDR 输出；HDR 映射到 SDR | 不请求 PQ 直通；不强制 scRGB 或开启系统 HDR |
| SDR 宽色域、传统桌面 | 可信 ICC 或已知目标色域／曲线 | 不把 BT.2020 源原色直接当显示原色 |
| Windows Advanced Color SDR | 独立 ACM 路线候选 | 核查 OS、活动显示和系统校色；不等同于 HDR 桌面 |
| Windows HDR 开启、目标能力已知 | FP16 线性 scRGB 作为首选验证候选，target 模式适配 | 记录真实协商值；目标峰值／黑位来源明确 |
| HDR 环境 scRGB 拒绝 | 验证 PQ／10bit 兼容路线 | 以保留暂停状态／视频轨的事务重建 VO；失败再回到明确 SDR 映射并提示 |
| HDR 状态或目标能力未知 | 显示未知，维持明确 SDR 目标或用户已确认模式 | 不擅自生成 1000 nits 或声称 HDR 直通通过 |

FP16 的独立实验及统一管理器已验证可建立交换链：rgba16f、linear、scrgb。它不是已通过 HDR 实机验收的默认方案。原色容器与显示器有效色域须分别处理；线性 BT.709 scRGB 可以通过负值／超范围值承载广色域，不能误把容器名称用作 SDR 色域裁剪依据。

输出格式／GPU 上下文改变可能需要重建 VO 或重启播放器，本轮已核查运行时可写性，发现逐项修改 D3D11 选项会重建 VO；已实现暂撤视频轨、批量写入、恢复原轨和暂停状态的事务。不可定位流不开放此 HDR 路线。不能假设菜单运行时 set 等同于成功重建；必要时提示按当前进度重载，远程文件、暂停状态和失败回滚一并验收。

### 分开管理五类亮度

1. 源 mastering／MaxCLL／MaxFALL／动态场景信息：反映片源，缺失不伪造为测量。
2. 显示器峰值：记录检测／Windows 校准／用户测量／回退值及来源；包含小窗口与全屏差异。
3. 黑位与对比度：零／未知不能混用；OLED 的 inf 只在确认或主动指定后采用。
4. HDR 桌面 SDR 参考白：优先系统查询，失败采用有说明的回退，避免固定写成 HDR 显示峰值。
5. 字幕／OSD 白点：文本按参考白，图形字幕另审计，不能靠过亮字幕判断视频 HDR 正确。

系统接口优先，兼容插件可选；没有 display-info 插件时也必须正常播放。缓存按当前窗口所在显示器失效，跨屏、Windows HDR／校色状态改变后重新查询。短暂失败可保留同显示器最后有效值并标为过期；不能跨显示器复用。失败退避、限频与有界重试，禁止反复切换交换链。

### 明确映射责任

常规路线采用 target 模式，并核对实际目标信息是否完整；上游在缺目标字段时可能用源字段补充，状态页必须揭示这种回退。源信息输出留作高级比较项，不命名为无条件“最准确直通”。HDR10／HLG 与不同峰值内容分别验收。

mpv、Windows、驱动、显示器都可能参与适配。记录各层状态、校准和显示器 tone mapping 设置；检查不需要压缩时的 PQ 亮度保真，以及超出显示能力时的高光／色域压缩，避免重复映射。不得为了“纯直通”默认关闭必要的高光适配或输出无法显示的亮度。

HLG 必须验证亮度加权 OOTF、黑位与峰值适配和彩色块，不能仅检查灰阶。HDR→SDR 为显示适配，不能对超出目标色容积的颜色要求无损复现；比较算法时先固定目标和参考映射。auto 曲线／色域映射可保留候选，记录实际算法及版本，先取消额外对比度恢复。

DV 分别列出 P5、P8、P7 MEL／FEL 的解码、RPU／重整形、基础层与 FEL 执行状态；未知标未知。HDR10+／HDR Vivid 同样区分格式识别与动态映射执行。不把 source-dynamic 的逐场景 HDR10 元数据输出称作原始 DV／HDR10+ 直通。

## 第三步：诊断和测量验收

扩展现有状态页，不新增一级菜单。显示源／有效输入／滤镜输出、目标配置及实际渲染目标、源与目标亮度、ICC／LUT／增强状态、Windows 活动 HDR 和显示信息来源。交换链格式、渲染纹理从可用 API／日志提取；查不到就未知，不能从选项请求值推定实际结果。链路位深与面板色准分别报告。

诊断按需采样，关闭停止；异步任务不重叠、切片旧结果失效，跨屏缓存更新。日志只摘取技术信息，避免导出网络播放凭证、历史路径或无关用户配置。

验收分三层：

| 层级 | 验证内容 | 通过依据 |
|---|---|---|
| 配置／功能 | 模式切换、缺组件、超时、链拒绝、恢复、硬软解、双字幕 | 无黑屏／残留错误目标，能解释回退 |
| 数学／GPU | 范围、矩阵、PQ／HLG、负值、FP16 量化、实际输出回读 | 与参考模型在预先制定的量化／浮点误差范围内一致；不以截图替代线性回读 |
| HDR 面板测量 | PQ 亮度、灰阶、色块、白点、ABL／局部调光、峰值适配 | 同机固定模式、图块尺寸和稳定时间，报告误差分布与仪器不确定度 |

素材覆盖 SDR 8／10bit、BT.2020／P3 SDR、HDR10 1000／4000 nits、HLG、DV 与动态 HDR；范围与矩阵包含正确标记、缺标记和错误标记。每项注明是否合成素材、软硬解、增强状态、系统校准、连接格式及测试版本。

比较 3FP、mpv、Windows 播放器时统一处理任务和显示环境，每组三次重复，记录测量漂移；HDR 色差用 ΔE_ITP，SDR 用 ΔE00。阈值在测量前按参考目标、量化下限和仪器能力制定，不挑图块或在结果出来后修改。无法访问第三方 GPU 输出时标记未取得，不拿截图冒充。

AMD 本机可完成配置和部分 GPU 验证；HDR 面板、NVIDIA／Intel、DV 实素材仍需外部实机。不同显卡不按档位改变色彩算法，只按能力选择后端与回退。性能评估附掉帧和渲染耗时，避免高精度路线不能持续播放。

| 顺序 | 交付物 | 完成条件 |

每阶段保留修改前配置、核心／运行库版本、校验值和独立实验参数。回退恢复完整色彩模式，不只改 target-trc。核心与组件更新后重跑代表素材和协商回归；不在本轮打包或发布，后续发布另按《发布流程.md》处理 Gate。

技术规则依据：[mpv 官方手册](https://mpv.io/manual/master/#options-target-colorspace-hint-mode)、[Windows Advanced Color](https://learn.microsoft.com/en-us/windows/win32/direct3darticles/high-dynamic-range)、前述固定提交与发行版核查。手册 master 会变化，实施时以本机选项能力和对应提交复核。

实素材性能案例见 [8K AV1 掉帧排查](8K-AV1掉帧排查.md)：本机硬解吞吐不足时，色彩配置不能补足解码缺口，极限性能与色准验收分别记录。
