# 全范围色度中点配置修复（2026-10-11）

**已在配置层修复当前核心全范围 10／12bit YUV 的色度中点偏差，默认启用；核心二进制未改，没有增加解码线程。** D3D11、Vulkan 的实际 GPU 输出、全码阶、PQ／HLG、ICC、硬解和滤镜交接验证通过。修复由 `portable_config/scripts/color-range-fix.lua` 执行，选项为 `portable_config/script-opts/color-range-fix.conf`。

这是一项针对已定位数值缺陷的色准修复。它增加受影响片源的 CPU 工作；OP 测试片是有限范围，不触发转换，也不会因此提高解码吞吐。此前发现的 FP16 写回量化仍然存在。默认 perceptual 色域映射和自适应 HDR→SDR 的完整独立算法参考仍待补齐，整条色彩管线的全面验收尚未完成。

## 修复方法

当前核心 `36bf3d529059a947d6700adefeab3b421e537c19` 的 gpu-next 在归一化源纹理后，把全范围 10／12bit 的色度中点按 16bit 存储计算。正确值应分别为 `512/1023`、`2048/4095`；实际 GPU 常量为约 `0.500007645`。根因和修复前反例见[原始软件审计](色彩管线软件闭环验证-20261011.md)。

脚本在实际渲染输入为全范围 10／12bit YUV 时追加单线程滤镜：

```text
zscale=rangein=full:range=limited,format=pix_fmts=yuv444p16le
```

420／422 保留对应采样格式。转换只重新表达数值范围，输出 16bit；不改分辨率、传递函数、原色和矩阵，不换缩放算法。以 10bit 为例，亮度和色度的参考映射为：

```text
Y16 = round(4096 + Y10 × 56064 / 1023)
C16 = round(32768 + (C10 − 512) × 57344 / 1023)
```

12bit 分母为 4095，色度中点为 2048。整数舍入存在，但全部输入码阶在转换后仍可逆算恢复，不把全范围直接裁成有限范围的原位深码阶。独立全码阶测试检查了每一个 Y／Cb／Cr 输入码值。

若实际输入是 D3D11VA 表面，滤镜先以明确的表面格式 `hwdownload,format=...` 下载，再做单线程转换；硬解器保留，受影响片源会增加 CPU 下载／上传，不能称为零复制。D3D11 实测使用 `d3d11va`，Vulkan 使用支持的 `d3d11va-copy` 路径；未全局改变硬解策略。

范围识别依据既有滤镜处理后的 `video-out-params`。有限范围、RGB、8／16bit、未验证矩阵／格式／核心自动旁路；外部滤镜先输出 RGB48 或 16bit 时不会重复转换。只支持已验证的 gpu-next 核心，更新核心后须重新验证，防止把此绕过方案无条件延续。

已有用户滤镜保留原序。改链后先撤销自身滤镜，再根据新的实际输出重新判断；用户主动删除、禁用或改写校正滤镜，本文件内不自动补回。文件结束撤销自身滤镜，下一个文件重新判断。`file-loaded` 时可能仍有旧 VO 参数，已改为等待新文件实际输出参数通知，防止把上一段全范围的判断套到下一段有限范围视频。

## 软件验证结果

沿用 i5-12600KF、RX6600、当前便携 mpv。GPU 数值测试固定输入和软件显示场景，通过实际纹理／交换链原始读回与独立公式比较；不要求屏幕测量。GPU 插桩只用于数值测试，播放开销另测。

| 验证 | 实测结果 |
|---|---|
| 全范围 10／12bit × 601／709／2020 NCL × D3D11／Vulkan | 12／12 通过；16 色块最大线性误差分别约 0.000395062／0.000460672，中性灰色块通道差为 0 |
| 转换后整数源 | 上述 12 组每帧三个平面全部 196,608 样本可恢复原整数码值 |
| 全码阶、灰阶及受控 PQ／HLG | 16／16 通过；10bit 全 1,024 码、12bit 全 4,096 码均保留；灰阶线性最大误差约 0.000488281／0.000500441 |
| 420 硬解 | 两个 API 均通过；硬解路径保留，实际输出 yuv420p16 limited，误差约 0.000395062 |
| 422 软解 | 两个 API 均通过；实际输出 yuv422p16 limited，误差约 0.000460672 |
| 非恒等 ICC Gamma2 | 709 全10bit／2020 全12bit、两个 API 共四组通过；10bit 交换链色块平均编码误差约 0.001226085／0.001887504，阈值 0.002 |
| 不适用旁路 | 全8bit、有限10bit、有限12bit、全16bit 四组保持源格式，不装校正滤镜 |
| 真实播放生命周期 | 外部 null／RGB48 改链、用户删除、暂停精确跳转、全→有限→全切片、同文件三次重载均通过 |
| 所有权／失败处理 | mock 验证用户滤镜保留、外部同名滤镜保护、删除尊重、添加失败回滚、结束后定时器不复装，通过 |
| 读回探针对照 | 更新 D3D11 immediate-context 钩子后，两 API 与仅交换链读回的全部 65,536 RGBA 像素逐字节一致 |

上述阈值是本次浮点回归的误差预算，不把两个后端一致当作独立正确性证明。PQ／HLG 采用目标峰值覆盖源峰值的受控数学场景，验证范围校正在 HDR 路线中的交接；不替代默认自适应 HDR→SDR 算法的完整参考。Vulkan HDR 尚未作为当前管理器支持场景，本轮 HDR 数值用 D3D11。

范围转换保留原整数码阶，不意味着最终显示整数无损：既有 FP16 写回仍使全范围 12bit 的 4,096 个灰阶得到约 4,001 个不同输出值。该量化没有被本修复消除；本修复消除的是错误的色度中点，而不是把整个管线升级成 FP32 存储。

## 实际播放代价

不附加 Frida／GPU 读回器的实际 mpv 对照，4K24 全范围 12bit FFV1，显示窗口 1024×576；固定 16 解码线程，校正滤镜 1 线程。每个 API 用基线／校正／校正／基线次序，预热 1.5 秒后测量 2 秒。

| API | 基线进程 CPU 毫秒／媒体帧 | 校正后 | 本轮平均增量 |
|---|---:|---:|---:|
| D3D11 | 204.838 | 213.346 | +8.508 |
| Vulkan | 187.475 | 199.219 | +11.744 |

CPU 时间是整个进程所有线程的 user＋kernel 总和，不是单帧墙钟延迟。短窗有波动，D3D11 两次基线为 198.088／211.589，不能把平均差当作所有片源的固定代价。八个窗口呈现／解码丢帧计数均为 0；这只证明本轮合成 4K24 窗口表现，不证明 OP 整片原速同步零丢帧。

选择自动启用的依据是已确认的色准错误，以及用户优先保留颜色准确性的要求。有限范围 OP 片源旁路，因此不会把这项额外转换施加到其上。
