# 滤镜恢复与色彩性能优化结果

日期：2026-10-06。按用户批准的四步计划实施，组件新版审计一并完成。保留既有菜单、个人设置和未提交修改；项目版本仍为 v1.5.7，本轮不提交、打包或发布，不修改发布流程。

## 最终行为

- `quality.lua` 是统一入口。DRBA-DML、DRBA-NV、SVP、ArtCNN-NV 恢复调用，所有增强允许主动尝试；HDR、广色域、倍率只提示。起播、菜单打开、滤镜选择不扫描组件、不核查显卡名、不校验整包、不模拟试跑，也不要求准备后再次点击。
- 真实滤镜初始化显示“启用中”，输出建立后显示“已添加”；实际失败保留具体方案与原始 traceback，撤回本次添加并恢复此前有效管理链。取消、新选择及切集使旧回调失效；外部滤镜和用户后来修改的同步、插值、去色带设置保留。
- 降噪 → 超分 → 补帧顺序固定，可叠加 Shader。上游尺寸／顺序变化时自动重建用户已选补帧。VS 同时请求帧数为 4，避免旧自动并发下的初始化争用；这是执行策略，不是显卡能力限制。
- 通用 RIFE 入口使用 DML；4.25 Lite、4.26、4.26 Heavy 分别调用真实对应模型。TensorRT 与 STD／NCNN 独立；STD 当前缺 `core.rife`，只有选择 STD 时实际报错，不阻止已有 ORT／DML。
- 能力明确时自动匹配显示目标；未知时使用 SDR sRGB 并说明未知项。用户及其他脚本的修改成为会话内手动覆盖，“恢复自动匹配”清除此覆盖；主动重选模式重新应用。
- 仅输出格式／色彩空间变化时撤轨重建。同显示器、同目标切集复用输出链；必要重建保留暂停、原视频轨、位置以及未改动的音轨／字幕。选项、恢复、重建／定位错误都报告失败，回滚到此前有效目标；恢复失败保留基线供重试。
- ICC 必须由用户明确选择；系统存在 ICC 不等于校准。ICC 与指定峰值按显示器身份及桌面 HDR 模式保存；手动 ICC 模式换屏后也只使用该屏已明确选择的描述文件，没有可信记录则回到 SDR。目标意图、实际设置、外部覆盖、峰值来源、输出标记、动态格式执行分别显示。
- 不自动切换 Windows HDR。HDR 输出采用 scRGB → PQ → SDR；峰值／参考白保持正确标尺，默认没有额外对比度恢复。支持 SDR、广色域 SDR、HDR→SDR 和软件模拟的 HDR→HDR／SDR→HDR 目标协商。
- 持久化只保留音量、设备、字幕等长期偏好与主动选择的性能档位；临时 `vf`、调色、片源修正不跨启动恢复。已有历史 JSON 未删除。

## 性能结果与默认推广

环境：Windows 11、RX 6600、ASUS VG249Q1A，1920×1080／165Hz SDR 桌面；mpv 0.41.0-1095、FFmpeg N-127165、libplacebo 7.374。相同 4K30 H.264＋AAC 素材、1080p 窗口、WASAPI 静音设备；正常 GPU 表面复制，`d3d11va-zero-copy=no`。每个候选预热 5 秒后至少采样 20 秒，重复三轮并交替次序。CPU 是 mpv 进程占一个逻辑核心的百分比，不是整机总占用，也不是 GPU 功耗。

| 路线 | CPU 中位数 | 三轮显示掉帧增量 | 音频欠载 |
|---|---:|---|---|
| 直接 D3D11VA／稳健 HQ | 6.586% | 0／10／0 | 未出现 |
| D3D11VA-copy／稳健 HQ | 17.104% | 42／300／56 | 1 次真实欠载（同一次事件两行日志） |
| 直接硬解／低功耗 | 5.678% | 0／1／0 | 未出现 |
| 直接硬解／高质量 | 6.095% | 6／26／21 | 未出现 |

所有候选媒体时钟推进比在 0.9979～1.0017；无解码掉帧／新增致命错误。直接硬解 CPU 中位数比 copy 低约 61.5%，三轮掉帧少于 copy。追加直接硬解稳定性采样（三轮、每轮预热 5 秒后至少 20 秒，逐半秒记录掉帧）均为零显示／解码掉帧、零音频欠载／错误，时钟比 0.9984～0.9992，断言无连续掉帧增长。本机默认改为 `hwdec=auto-safe`；已知 CPU 滤镜在起播阶段用当前文件的兼容 copy 路径，播放中加入 VS 时由 mpv 下载表面，用户明确指定的后端不覆盖。保留手动 `d3d11va-copy`／软解回退和独立实验零复制。

稳健档沿用 HQ。低功耗以 bilinear 空间缩放关闭高级缩小；高质量使用 spline36 色度恢复和线性缩小。高质量在本机掉帧更多，保持手动可选；三个档位都不改色彩目标、不自动开补帧或去色带，也不自动降级。

HDR 峰值分析使用同一 640×360 HDR10 夹具、SDR 输出，各预热 3 秒后至少 20 秒，三轮均无掉帧。开／关 CPU 中位数 6.362%／0.614%，波动较大且关闭会改变亮度映射；因此保持 `auto`，不把省算力当成色准收益，不外推到 4K HDR。

长 GOP 28 秒 H.264 固定五个精确目标，开／关跳过中间帧各三轮；位置误差小于 0.1 秒，耗时中位数约 0.075／0.138 秒。只有本地暂停视频夹具，未覆盖 SVP／音频同步和更多解码路径，暂不推广，保留手动入口并修正原错误“音频同步模式”名称。

新增管理任务起播对照使用同一完整配置，移除五个管理脚本作隔离对照，各三轮。IPC 视频信息就绪中位数约 0.586／0.585 秒，首次画面日志中位数 0.665／0.637 秒；首次冷缓存两组均更慢，没有稳定收益支持进一步删减既有起播任务。此短测不作为稳态性能推广依据；确认没有新增组件预检。

## 运行与回退

活动配置直接生效；重启播放器后使用「视频滤镜」／「着色器」入口，首次真实模型或引擎构建等待完成即可。色彩恢复入口在「画面 → 色彩目标」，整体临时增强恢复在「工具 → 画质处理」。性能现已移至「其它 → 播放性能」手动选择（2026-10-07 后续调整）。

本轮前快照在 `backup/optimization-20261005-before/`，配置、K7sfunc 1.3.1 与旧 VSORT 配套运行库按源路径保存；旧 SVP 重复文件也在其中。需要回退时先退出播放器，只恢复对应源路径，不整包覆盖当前工作区；K7sfunc 回退需同时换回匹配包目录和 dist-info，VSORT 需恢复 DLL 与对应依赖，zsmooth 可以留存。主配置备份中的硬解默认已还原为 copy，其他既有编辑保留。不要从用户历史恢复临时 `vf` 或片源修正。

原始测试日志／素材／长 GPU timing 样本在忽略目录 `tmp/modernization/validation/` 与 `tmp/modernization/optimization-20261005/`；可跟踪的摘要在[结果 JSON](optimization-results-20261006.json)。稳定性补测命令为 `python.exe -X utf8 tools/benchmark-playback.py --verify-direct`。维护命令见 `tools/README.md`；HandShake 状态与中文进度同步更新。此前报告记录的是历史状态，本文件描述当前实现。

本机 `mpv.com --no-config --vd=help` 列出 AV1／dav1d 等解码器，没有 AV2 解码器；当前这版不能依靠内置解码器播放 AV2，不把 AV1 支持当 AV2 支持。
