# 起播窗口显示顺序修复（2026-10-08）

新启动播放器、主动打开新媒体和从最小化状态打开媒体时，把窗口抬到普通窗口前面。持续置顶仍由原菜单和保存偏好控制；暂停／继续、精确跳转和自动播放下一集不会反复抬窗。

本机 `window_size_position.conf` 保存了 `ontop=no`，会覆盖主配置的 `ontop`。这是用户偏好，不应以永久置顶代替起播抬窗。Windows 下 mpv 的 `focus-on` 选项不适用于该路径，见 [mpv 手册](https://mpv.io/manual/master/#options-focus-on)。

真实回归用完整隔离配置、HEVC10 播放夹具和自有普通遮挡窗口：旧版新启动／IPC 重新打开后都仍在遮挡窗口下面；新增脚本后均抬到上面。仅调用 `SetForegroundWindow`／普通 `HWND_TOP` 在本机受后台激活限制时不足以改变顺序，见 [微软前台窗口规则](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)。

新增 `window-foreground.lua` 和匹配选项 `window_foreground.conf`，默认启用。优先申请前台焦点；被系统拒绝时用原生窗口层级短暂抬升并立即恢复普通层级，不修改 mpv `ontop` 或持久文件。原有持续置顶窗口保持其层级。[SetWindowPos 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)区分普通窗口和持续置顶窗口；普通窗口仍位于其它持续置顶窗口之后。

窗口尚未创建时最多等待两秒；拿到有效句柄后停止重试，媒体结束／退出时取消。非 Windows 或无 LuaJIT FFI 时直接退出。最小化恢复同步更新 mpv 状态，使自动暂停配置正常恢复。

`tools/test-window-foreground.py` 已验证：

- 旧版遮挡复现与修复后的新启动、IPC 重新打开。
- 最小化恢复，原生持续置顶位与 mpv `ontop` 仍为关闭。
- 保存选项仍为 `ontop=no`。
- 原来已开启的持续置顶仍保持开启，原生 TOPMOST 位和 mpv 选项一致。
- 暂停／继续、自动播放下一集不抬窗。
- 日志无 error／fatal。

键盘焦点和显示顺序单独记录；本机系统拒绝部分后台焦点请求时，显示顺序仍已修复，不能声称强制取得键盘焦点。未修改系统前台锁、发送模拟键盘输入或操作其它应用窗口。

原始结果：`tmp/release-prep-20261008/window-foreground-results.json`。开关为 `portable_config/script-opts/window_foreground.conf` 的 `enabled`；回退可将新增脚本移出活动 scripts 目录。
