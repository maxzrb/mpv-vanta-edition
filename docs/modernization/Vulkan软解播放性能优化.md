# Vulkan 软解播放性能优化

本轮在现有核心、不重编译的条件下，找到有效的配置组合：**Vulkan＋视频解码异步队列**。它保留原位深、色度、HQ 缩放、线性缩小及 Windows SDR ACM 的 FP16/scRGB 输出。在样片同条件的三轮约 20 秒窗口中，掉帧从 D3D11 的 548／579／636 帧降至 55／65／56 帧，音频欠载均为零。这个结果不能替代整片满帧验收。

## 条件与比较范围

- 本机 i5-12600KF、16 逻辑处理器、RX 6600、32 GiB 内存；测试时其它用户程序继续运行，未修改系统电源设置或终止其它应用。
- 样片 `OP-yuv444p12-SWTest.mkv`：3840×2160、AV1 Professional、12bit 4:4:4、约 47.95 fps、FLAC 与 ASS 字幕。
- 核心仍为 `v0.41.0-1107-g36bf3d529`；FFmpeg `5d4755f7d`、libplacebo `0d043c7f6f79cd3687c023454bdacbe615e4d96f`，未替换运行时。
- 完整配置复制到忽略目录：保留字幕与音频，音量设为零；1280×720 可见窗口，从 10 秒起播、预热至约 15 秒后测量约 20 秒。
- 主对照固定 dav1d 32 工作线程／32 帧深度；保持 `framedrop`、同步方式、滤镜、缩放及色彩参数。报告实际呈现掉帧，不将媒体时钟比例换算为呈现帧率。
- 初轮自动深度因空闲内存变化为 24／28，未纳入固定 32／32 主对照。

## 短窗结果

| 设置 | 窗口掉帧 | 音频欠载 | 结论 |
|---|---:|---:|---|
| D3D11，32／32，修正徽标后 | 548／579／636 | 各 1 次 | 主对照 |
| D3D11，交换链深度 8 | 512／632 | 1／2 次 | 无稳定收益，不采用 |
| D3D11，关闭主要 UI 脚本 | 576 | 1 次 | 无改善，不删减功能 |
| D3D11，48／48 | 454／428 | 3／2 次 | 更耗内存，未达到目标 |
| Vulkan，32／32，不开异步队列 | 263／269／157 | 各 1 次 | 有收益，仍有阻塞 |
| Vulkan，32／32，16 帧／768 MiB 队列 | 55／65／56 | 均 0 次 | 有重复证据，加入可选预设 |
| Vulkan，32／32，关闭直接渲染＋队列 | 104 | 0 次 | 不优于上述组合，不采用 |
| Vulkan，48／48，无队列 | 39 | 1 次 | 单轮结果，仅候选 |
| Vulkan，48／48＋队列 | 7 | 0 次 | 单轮结果，峰值约 9.5 GiB，不自动采用 |

32／32 的 Vulkan＋队列平均掉帧约 58.7，D3D11 约 587.7，短窗约减少 90%。三轮音画偏差采样峰值为 3.734／98.779／1.926 ms；内存峰值约 7.25～7.30 GiB，队列较不开队列额外约 0.7 GiB。

Vulkan 不开队列的前两轮使用隔离色彩原型；最后一轮及组合队列测试使用正式脚本，省去了与 Vulkan 无关的 D3D11 输出选项写入。D3D11 分支保持原有行为。测试顺序、日志和实际选项保存在原始 JSON 中，单轮差异不当作确定收益。

## 为什么现有核心可以改善

当前 libplacebo 的 D3D11 CPU 平面上传使用 `UpdateSubresource`；Vulkan 的 CPU 上传使用自己的 host transfer／PBO 传输路径。切换后端能使用现有的另一套上传与提交实现，不需要把 VSPlayer 的 DYNAMIC／WRITE_DISCARD 实现编译进当前核心。具体收益是实测结果，不能只从 API 名称断言每个驱动都更快。

异步队列把解码从播放器供帧流程移到独立线程。它在 D3D11 上之前没有稳定视频收益，但与 Vulkan 合用后能显著减少阻塞和欠载。队列改变帧调度与缓冲，不进行位深转换。

**不能把这里解释为 dav1d 已直接解码到 Vulkan 映射缓冲。** 当前 FFmpeg 的 libdav1d 使用自己的 `AVBufferPool` 图像分配器，而非 mpv 的 `get_buffer2_direct`。`vd-lavc-dr=auto/no` 的单轮差别不是直接渲染生效的证据。Vulkan 缺少 `upload frame` 统计项也不能说明上传成本为零。

固定源码：[FFmpeg libdav1d 分配器](https://github.com/FFmpeg/FFmpeg/blob/5d4755f7d/libavcodec/libdav1d.c)、[libplacebo D3D11 上传](https://github.com/haasn/libplacebo/blob/0d043c7f6f79cd3687c023454bdacbe615e4d96f/src/d3d11/gpu_tex.c)、[Vulkan 上传](https://github.com/haasn/libplacebo/blob/0d043c7f6f79cd3687c023454bdacbe615e4d96f/src/vulkan/gpu_tex.c)、[mpv 解码异步队列](https://github.com/mpv-player/mpv/blob/36bf3d529059a947d6700adefeab3b421e537c19/filters/f_decoder_wrapper.c)。

## 画质与色彩核验

1. Vulkan 实际协商为 `VK_FORMAT_R16G16B16A16_SFLOAT`＋`VK_COLOR_SPACE_EXTENDED_SRGB_LINEAR_EXT`；不是只把渲染目标属性标成浮点。
2. 原始交换链读回标尺保留负值和大于 1 的值：包含 -0.125、0.5、2.54，FP16 存储读回 2.5390625。
3. SDR ACM 参考白及 1024 灰阶、广色域独立数值参考、线性黑白缩小通过；没有降至 8／10bit 输出或提前裁剪广色域负分量。
4. PQ／HLG 源在本机实际 SDR ACM 桌面的 16 色块映射，与 D3D11 的原始 FP16 读回一致。此项不注入 HDR 桌面能力，不冒充真实 HDR 桌面验收。
5. 样片 10.010 与 25.004 秒精确帧，软件高位深源截图一致，仍为 `yuv444p12`；ASS 字幕仍选中。两后端原始 FP16 输出不是逐位一致，最大绝对差均为 0.0009765625，RMS 约 0.0000183／0.0000243，符合同精度渲染的数值误差范围；没有用“源截图一致”代替实际输出核验。

Vulkan 读回工具仅附加到自有诊断进程。在驱动报告允许时，为诊断交换链增加 `TRANSFER_SRC` 用途，暂停画面后复制到暂存缓冲读取；不修改色彩或图像数据。性能测试和日常播放不加载该工具。测试范围是软件参考与呈现前 GPU 存储值，未测量 DWM 后输出或物理面板色准。

## 已落地改动与使用

`AV1-SoftDecode-Vulkan` 是可选预设：`gpu-next`、Vulkan、软解、16 帧／768 MiB 异步队列。线程／帧深度仍由现有 `decode-performance.lua` 按资源预算选择，不强制 48／48。当前默认 D3D11、普通硬解及实际 HDR 桌面路线不变。

```powershell
& "C:\Program portable\mpv2\mpv.exe" --profile=AV1-SoftDecode-Vulkan "C:\Users\maxzr\Downloads\OP-yuv444p12-SWTest.mkv"
```

在播放前启用；关闭该实例并正常启动即使用默认路线。此预设按本机 SDR ACM 验证，实际 HDR 桌面继续使用默认 D3D11。不同驱动仍须成功协商 FP16/scRGB；失败时脚本会报告并回退，不把 10bit sRGB 误报为浮点 ACM。

另修正徽标脚本的资源判断：4K 及以上 AV1 的实际软件解码都优先用已有画面定位，而非仅检查自动调优的 userdata。手动线程／关闭调优时，明亮画面也不再无条件启动额外 FFmpeg 解码；暗场仍按需后瞻，后台单线程，停止／换模式取消通过。

## 整片验收

实际可选档整片播放（从 0 秒开始，自动并行选择 32／32）：92.09 秒视频用时 92.408 秒，累计呈现掉帧 1953 帧、解码丢帧 0、音频欠载 0，音画偏差采样峰值 1.483 秒，峰值工作集约 7.36 GiB。后半段重场景仍严重掉帧，未达到稳定满帧。

首次整片实验受自动连播影响，越过样片后进入其它文件，结果作废；重跑关闭测试副本的自动连播并核对单条播放列表／当前路径。48／48 扩展整片实验收到窗口退出按键提前结束，不计入整片证据，不以单轮 7 帧短窗推广高内存设置。

最终预设的暂停精确跳转、ASS 字幕选择、停止后恢复 D3D11 普通 HEVC 硬解与队列关闭已通过；该档开启队列后的两帧源截图及实际 FP16 输出也已重新核对。D3D11 固定 32／32、不开异步队列的整片对照：用时 93.112 秒、掉帧 2974、解码丢帧 0、音频欠载 10 次、音画偏差峰值 2.211 秒、峰值工作集约 6.85 GiB。与实际 Vulkan 预设单轮整片对照，掉帧减少约 34.3%，欠载从 10 次降为零；不能把短窗约 90% 的改善外推至整片。

后续用户明确要求不再增加线程，并以默认 D3D11、跨片源与跨后端通用性作为优化标准。详见[通用播放性能优化研究](通用播放性能优化研究.md)：大队列存在反例，未推广为默认；徽标后台预算已改为所有真实软件解码视频共用。此前可选 Vulkan 预设保留为单独选择，不代表新的全局推荐。
