# SDR ACM 与 FP16 输出优化（2026-10-08）

本轮按“SDR／HDR 色彩准确优先”的方向修改本地配置和核心，不发布、不改变项目版本。增强模块仍是可选功能；本轮没有增加模型或默认增强。

## 菜单与默认设置

- 移除 bilinear 主缩放的低功耗档及其持久化映射。旧低功耗偏好不再生效，回到默认 HQ；用户主动保存的高质量档仍保留。
- 一级菜单“其它”整体移到“工具”和“最小化”之间。
- “视频滤镜 → 清空全部视频滤镜”直接可达，移除“管理”中间层及重复的全组关闭入口。清空会删除全部 VF，包括外部滤镜；Shader 单独清空。
- 默认 HQ 与高质量均使用线性缩小；高质量主要提供另一种色度重建选择。默认 HQ 的 `cscale=bilinear` 是色度重建参数，原低功耗档的 bilinear 主缩放已删除。

## 原生显示识别与色彩处理

新增只读 Windows DisplayConfig 查询，区分经典 SDR、SDR ACM（WCG）和 HDR。按当前窗口匹配实际输出；镜像目标不唯一或旧接口无法区分时报告未知，不猜测 HDR。没有修改系统 HDR、注册表、校准文件或显示驱动设置。

本机 ASUS VG249Q1A／RX 6600 当前为 SDR ACM。旧 display-info 插件仅报告 HDR 不支持，遗漏了 ACM 状态。新增检测只补充该能力，不替代旧插件的其它显示信息。

SDR ACM 使用线性 BT.709 FP16 scRGB，线性 1.0 对应系统管理的 SDR 参考白；内部 80 的编码标尺不是物理面板亮度测量。Windows 负责最终显示校色，播放器不叠加显示 ICC。经典 SDR 保留 sRGB 和用户明确选择的 ICC 路线；可信偏好记录当前显示身份、桌面模式和系统 ICC 报告路径，关联改变后停止自动复用。ACM 下 GDI 的 ICC 报告可能是兼容描述文件，不能据此声称读到了系统实际校准数据。

scRGB 输出显式不做物理连接位深的前置抖动。默认自动黑位改为标准工作空间的零黑位，避免用未实测的驱动黑位报告抬黑或改写 HDR 绝对亮度；用户显式指定的对比度仍保留。最终量化与显示校准交给 Windows／驱动，HDR 峰值仍采用当前显示器报告或用户保存的可信值，SDR 没有反向映射为 HDR。

输出格式与色彩空间通过同一 `apply-profile` 原生命令配对更新，避免逐项修改时创建不兼容交换链。独立加载管理器但没有配套 profiles 的环境仍能降级运行。恢复时把核心返回的空色域规范化为等价的 `auto`，并保留事务回滚、恢复重试及用户覆盖所有权。

## 修复最终浮点截断

旧核心内嵌 libplacebo `92b5ac6`，其最后一步无条件把输出夹到整数信号范围 0～1。即使交换链是 FP16，scRGB 高光及表示广色域颜色的负分量仍被截断。旧 GPU 截图测试先在 OUTPUT hook 编码测量值，因而没有暴露最后一步的错误。

原始 GPU 读回证实了该问题。修复来自官方 [libplacebo 提交 99e80abd00b2e1be1a8a6ac0ff66b500cacdebda](https://github.com/haasn/libplacebo/commit/99e80abd00b2e1be1a8a6ac0ff66b500cacdebda)，只对非浮点格式保留整数范围限制。本地核心更新为 [shinchiro 20261008 标准 x86_64](https://github.com/shinchiro/mpv-winbuild-cmake/releases/tag/20261008)：

- mpv `v0.41.0-1107-g36bf3d529`。
- libplacebo `v7.374.0 (v7.360.0-152-g0d043c7-dirty)`，已核实包含上述修复。
- 内嵌 FFmpeg `N-127242-g5d4755f7d`；没有把独立 ffmpeg 工具当作内嵌解码器。
- 下载归档 SHA-256：`33804484e60da3d4a44392d58836ea707e198ca4c3103ae1c39d4dd099c67122`，与官方 asset digest 一致。

先验证隔离核心再替换匹配的 mpv.exe／mpv.com、随附编译器 DLL 和手册；编译器 DLL 与旧版哈希一致。来源、新旧文件校验及备份路径见 [核心清单](color-output-core-manifest-20261008.json)。其它第三方运行时和用户安装／关联入口没有按归档整体覆盖。

## 原始 GPU 数值结果

维护探针只注入自己创建并暂停的测试 mpv。在 Present 线程复制实际交换链至只读 staging，直接解释 RGBA16F 原始字节，并记录成功设置的 DXGI 色彩空间。没有使用 PNG 编码承载这些浮点结果，没有改变视频像素。

| 回归 | 结果 |
|---|---|
| 读回标尺 | 0.25／0.5／0.75 精确一致；2.54／−0.125／1.25 读为 2.5390625／−0.125／1.25 |
| SDR ACM 灰阶 | 1024 级全部保留；最大线性误差约 0.001093，零黑位与参考白通过 |
| BT.2020 SDR 色块 | 最大线性误差约 0.000566；负分量与超过 1 的分量保留 |
| PQ 色块 | 最大线性误差约 0.006924，按 HDR scRGB 标尺折合约 0.554 nits |
| HLG 色块 | 最大线性误差约 0.007813，按 HDR scRGB 标尺折合约 0.625 nits |
| 黑白交替条纹 2:1 缩小 | 非线性输出均值 0.213867；线性输出均值 0.499756，接近正确平均 0.5 |

灰阶容差 0.00125；色块采用绝对误差加相对误差 `0.00125 + 0.002×|参考值|`，覆盖半精度量化与 GPU 运算误差。参考由源整数码值独立重建矩阵、sRGB EOTF、PQ 与 HLG OOTF，不用被测 GPU 输出生成参考。

SDR ACM 是本机实际桌面路线。PQ／HLG 在 SDR 显示器上注入 HDR 能力，并隔离真实 SDR 桌面提示及参考白覆盖，验证数学与浮点输出；这些不是实际 HDR 桌面或面板验收。浮点存储 16bit 只有约 10bit 尾数，不能等同于整数 16bit 有效精度。交换链和已观察纹理不证明每个中间阶段、增强模型、DWM、驱动和面板都是 16bit。

## 播放回归与边界

固定 4K→1280×720、直接 D3D11VA、完整配置、WASAPI 静音、预热 5 秒后至少采样 20 秒，线性／非线性各三轮交替次序。六轮时钟比例 0.99869～1.00017，显示／解码／延迟／错时计数增量均为 0，没有错误或音频欠载。GPU fresh 阶段平均耗时之和的中位数由 2.021735 ms 到 2.051011 ms，约增加 1.45%；CPU 单核心占用中位数由约 5.99% 到 7.36%。这些是本机合成素材结果，不推广到其它显卡或所有素材。性能测试不加载 GPU 读回探针；普通播放没有增加组件扫描、播放前解锁或模拟试跑。

真实菜单结构、清空 VF 与 Shader 的独立性、默认 HQ、十二组 Anime4K、切片恢复及原生菜单截图目检通过；H2648／HEVC10 直接硬解、WASAPI 静音设备、双字幕、DRA 徽标和 HTTP 播放通过。经典 SDR 的 601／709／2020、8／10／16bit 五组基线与 CCD 像素回归通过，16bit CCD＋RIFE 长片／跳转保持；HDR10／HLG 静态组合及模拟 scRGB 恢复通过。可信 ICC 的跨启动、显示身份与关联变化隔离通过，Lua 状态机包含配置组部分失败的回滚。完整结果见 [软件与 GPU 回归摘要](color-output-results-20261008.json)。H26410 菜单截图素材在本机自动回退软件解码，不能拿它声称 H26410 硬解通过。

当前验证不包含仪器屏幕测量、真实 HDR 桌面、NVIDIA／Intel、动态 Dolby Vision 全路径。它们仍为可选后续实机补充，不妨碍本轮已授权的软件验证完成。
