# 3FP 精度对照与映射数值验证

日期：2026-10-12。只验证软件，不要求真实 HDR 屏幕或校色仪。核心保持 mpv `36bf3d529`／libplacebo `0d043c7`，默认 D3D11、HQ、既有解码线程数保持。本轮没有修改生产色彩参数。

## 对用户问题的明确结论

**按 3FP 公开代码实际采用的主图像精度等级，我们达标。其实现也是 FP32 运算、FP16 中间存储与 HDR 输出；全程 RGBA32F 不是它的高色准要求。** 3FP 确实使用 32 位：常规 Shader 的浮点运算，以及动态曲线的单通道 `R32_FLOAT`。只说“3FP 没用 32 位”也不准确。

精度等级与色彩转换正确性分别核验。矩阵、范围、传递函数、映射方法及输出空间需要正确配合，增加存储位数不能纠正错误公式。实际 HLG 同源验证支持我们这条路线；默认 perceptual 表仍有可量化的近似误差，配置层可以提高表密度，不必改为全程 32 位纹理。

3FP 公开的内核对照工具检验“优化前后等价”，没有给出整链绝对色准的 ΔE 合格线。不能凭项目自称高色准，推导所有片源与所有算法的绝对验收要求。

## 固定源码与实际编译证据

核查 3FP 提交 `20bcc001b24f6b6de4575bddf9b93ec452795b0d`。读取两个公开字节码头文件，对 10 个 DXBC 数组调用本机 `D3DDisassemble`，没有启动或重编译 3FP。

| 环节 | 3FP 固定公开实现 | 我们实际 GPU 路径 |
|---|---|---|
| 源整数上传 | 8 位 R8／高位深 R16_UNORM | R8／R16；既有逐像素验证保留源码值 |
| 浮点运算 | `ps_5_0`／`vs_5_0`，无 min16/min10 声明 | D3D11 实际 DXBC 常规 FP32；Vulkan SPIR-V 浮点类型 32 位 |
| 缩放／主图像中间纹理 | R16F／RG16F／RGBA16F | 主图像实际 RGBA16F |
| HDR／scRGB 输出 | RGBA16F、BT.709 线性、1.0 = 80 nit | 相同；实际交换链格式及提交空间核对 |
| 经典 SDR 输出 | 按策略 BGRA8 或 RGB10 | 本次经典 SDR 实际 RGB10，空间抖动 |
| 动态曲线辅助纹理 | R32_FLOAT | 本次实际色调曲线表 R32_FLOAT |
| 全程 RGBA32F | 源码没有这种要求／格式 | 不需要据此强制开启 |

代码位置：[VideoRenderer.cpp](https://github.com/Lake1059/FFF_Project/blob/20bcc001b24f6b6de4575bddf9b93ec452795b0d/FFF.Native/3FP/Render/VideoRenderer.cpp)：179（输出策略）、2817（交换链）、3186（R32 曲线）、3243（整数源平面）、4241–4243（缩放中间 FP16）、847–853（scRGB 单位）。[字节码生成](https://github.com/Lake1059/FFF_Project/blob/20bcc001b24f6b6de4575bddf9b93ec452795b0d/tools/generate_shader_bytecode.py)使用 fxc 的常规 SM5 目标。

Vulkan 峰值统计模块出现两个 `RelaxedPrecision` 装饰；逐 ID 类型检查确认为**整数**，不是浮点色彩运算。本轮读回器增加类型分类，要求所有浮点声明为 32 位、无浮点或未知类型的 RelaxedPrecision；没有为测试通过而放宽浮点要求。历史“不存在任何 RelaxedPrecision”的结论仅适用于当时测到的那些 Shader，不能泛化至所有模块。

3FP [compare-kernel-pixels.py](https://github.com/Lake1059/FFF_Project/blob/20bcc001b24f6b6de4575bddf9b93ec452795b0d/tools/compare-kernel-pixels.py)：8/10 位优化对照容差为一个目标码值；FP16 对照要求优化前后字节一致。导出文件使用 float32 编码不代表实际渲染目标为 RGBA32F，也不代表 FP16 对真实连续信号零误差。

## HLG 同源参考：公式比位数更关键

条件：黑位 0、参考峰值 1000 nit，16 位有限范围 BT.2020 YUV，16 色块。先由实际整数 YUV 逆算编码 RGB，再独立执行 HLG 逆 OETF、以 BT.2020 加权亮度应用 OOTF，得到参考 nit；mpv 用实际 scRGB 交换链原始像素验证。

3FP 公开基础 Shader 的 `HlgToNits`（512 行）对三个通道分别执行 `scene^1.2 * 1000`。标准 1000 nit 条件需要共同的亮度因子 `Y_scene^0.2`。灰色上两个公式相等，彩色上会不同；只测白／灰会漏掉这类错误。

| 同源编码色块约为 (0.75, 0.25, 0.25) | 相对标准参考最大等效 BT.2020 通道误差 |
|---|---:|
| mpv 实际 GPU 输出 | 0.0883895 nit |
| 3FP 公开基础公式复算 | 41.3315851 nit |

mpv 全 16 色块最大等效通道误差 0.570021 nit，最大值出现在高亮色块。**3FP 这一列是源码公式复算，绝不是 3FP 播放器实测或所有路径的优劣排名。** 这已经足以说明 FP16 存储不妨碍采用正确的 HLG 公式，不能把“纹理不是 32 位”直接等同于色准路线错误。

## 默认 HDR→SDR 静态场景闭环

新增独立 float64 模型，分别计算整数峰值统计、PQ 虚拟目标及曝光、ST2094 膝点、双曲 spline、LMS film 响应、原色转换、输出编码；不调用播放器内部函数，不从实测值拟合曲线。

实际播放仍使用 `tone-mapping=auto`、`hdr-compute-peak=auto`、默认百分位约 99.995、对比度恢复 0。诊断目标固定 SDR ACM 白位 80 nit、黑位 0，比较 D3D11/Vulkan 和曲线表 256/1024 节点。PQ1000 灰阶、PQ4000 灰阶、PQ4000 彩色、HLG 灰阶，共 **16 组全部通过**。

| 测试 | 默认 256 点，两 API 最大线性 scRGB 误差 |
|---|---:|
| PQ1000 灰阶 | 0.000482347 |
| PQ4000 灰阶 | 0.000485650 |
| PQ4000 彩色 | 0.000654481 |
| HLG SDR 目标适配 | 0.000488301 |

包含 1024 点候选的全 16 组最大误差 0.000672304。一个 scRGB 单位为 80 nit，因此最大通道差约 0.0538 nit。1024 点没有一致改善最终数值，未启用。

两项必须计入参考的实际行为：

1. PQ 峰值统计计算与后续色调映射之间存在**编码域** FP16 写回。本机实际 16 色块符合向零量化，逐像素中心与独立量化预测完全一致。曲线公式测试必须纳入该阶段，不能把遗漏写回的参考误差误报成 tone map 算法错误。未经这个表示步骤的端到端连续源误差会更大；分项通过不意味着量化消失。
2. HLG 输出到 80 nit SDR 时，核心推导低亮度目标系统 gamma；不是固定按 1000 nit 渲染、再套 PQ 的 spline。实际路径无额外 spline，参考采用相同目标亮度下的 HLG 显示适配。初版固定 1000 nit 参考不适用于这个目标，已纠正。

这些是静态场景数值验收，不是场景切换的 IIR／延迟峰值时序测试。

## 默认 perceptual 色域映射：能复现，有提高精度空间

16 位全范围 BT.2020 SDR 的 16 色块，含饱和蓝等彩色和中性灰，目标经典 SDR sRGB／80 nit／黑位 0。独立连续 perceptual 模型和独立表模型分开：后者重建 48×32×256 I/C/h 网格、CPU PQ 近似、RGBA16_UNORM 量化和三线性采样。

默认表模型与实际 RGB10＋空间抖动读回的最大编码差为 0.00114767；96×64×256 表为 0.00131086。两个 API 一致，证明先前连续模型与 GPU 的差异主要来自表近似，而不是“错把默认 perceptual 当纯矩阵”。模型按预设 0.002 编码容差通过；这不是一个公开的绝对 ΔE 认证。

| 表配置 | 实际输出对连续算法最大 sRGB 编码差 | 最大 ΔE76 | 平均 ΔE76 |
|---|---:|---:|---:|
| 默认线性 48×32×256 | 0.0420323 | 2.21835 | 0.20640 |
| 加密线性 96×64×256 | 0.0191828 | 0.94610 | 约 0.1235 |

ΔE76 是 D65 CIELAB 欧氏距离，与该映射算法连续输出相比，不是和原始 BT.2020 颜色相比，也不是 ΔE00／屏幕测量。不能仅据 16 色块给全部颜色下结论。

此配置可以在现有核心尝试：

```text
--libplacebo-opts=lut3d_size_I=96,lut3d_size_C=64,lut3d_size_h=256
```

保留原 perceptual 算法与线性插值，但主表由约 3 MiB 增至 12 MiB，生成与缓存成本需要独立测量。本轮未加入默认，避免未经性能验证便声称无代价提高色准。三次插值候选导致部分灰块额外偏色，未采用；ICC 表上限 128³ 的八组对照没有降低最大误差，也未采用。

## HDR 映射与色域映射组合

彩色 PQ4000 →经典 SDR RGB10，再验证自适应映射、默认／加密 perceptual 表、输出编码和抖动的**组合**。实际峰值统计仍开启；同一来源整数值独立推导参考，编码域 FP16 中间值另作等值断言，不将实测中间值拿来拟合参考。

四组通过：默认表最大编码差 0.000831504，加密表 0.000649819，D3D11/Vulkan 相同。这里计入所选表的表示近似，不能将此小误差替换成“相对连续色域算法也零误差”。
