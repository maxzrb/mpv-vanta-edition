## 当前问题

- 画面相关功能分散在「画面、视频、画质增强、视频滤镜、其它」，用户需要先理解底层实现才能找功能。

## 着色器的可发现性

入口固定为 **画面 → 着色器**，去掉「高级 Shader → 专家库」两层包装。

- 常用预设：沿用现有收藏和完整配置组合，如 Anime4K、Ani4K／AniSD、FSRCNNX、Ravu、SSIM。完整组合不能简化成单个文件而改变效果。
- 完整算法库：按现有 Shader 文件分类保留，包含 Anime4K、ArtCNN、CuNNy、AMD、FSRCNNX 等，分类内按名称选文件。移除重复展开的第二套完整用途索引，文件不删除。
- 当前启用 Shader：列出实际启用项、来源与开关／移除操作；明确哪些来自推荐系统、哪些是手动项。

日常通用／动画超分在着色器分区快速选择，AI 超分在 VS／AI 分区选择。快捷入口引用同一方案与状态，不独立维护另一份处理逻辑。其他手动预设必须在状态页体现，并防止与推荐 AI 重复超分。

## 可选包与能力检查（按用户补充意见调整）

分发中的着色器组件和 VS／AI 滤镜组件可以独立缺失，菜单不能假定用户装了全量环境。「nv 滤镜」若指 NVIDIA 专用后端，还必须区分软件安装与显卡支持两项条件。

- 着色器分区只检查所需 GLSL／预设链的全部文件，不依赖 Python 或 VS；Shader 同样是可选组件，不把基础包存在视为 Shader 已安装。
- VS／AI 分区核查 Python、VS、辅助函数、选中后端、必要 DLL、模型及实际准备结果；不能因为配置文件或一个 DLL 存在就显示可用。
- NVIDIA 专用方案必须另外检查对应显卡／后端能力。安装了 NVIDIA DLL 不代表 AMD／Intel 可以使用。
- 首次打开菜单按需检查；首次准备才做完整锁定与推理验证。启动／普通播放不主动导入所有可选运行时或加载所有模型。
- 缺少整类组件时保留简洁灰色入口，例如「VS／AI 滤镜 · 未安装」，点进状态说明缺失项与对应组件说明，避免展开大量不能执行的命令。状态说明可以访问，执行增强按钮不可用。
- 已安装类内按具体方案检查文件和依赖，缺少单个模型仅影响该方案。可重试的准备失败保留重试入口，硬件不支持明确说明原因。
- 安装／补齐组件后可手动重新检测；菜单状态说明是检查时的结果，启用前再校验，避免检查后文件被删除仍执行。
- 以实际文件和能力为准，包安装标记仅作提示；兼容手动解压、只更新配置和选择性复制组件。

验收至少包括基础播放、仅着色器、仅 VS／AI、两者均装、缺单个模型／DLL、AMD／Intel 带 NVIDIA 文件等环境。包结构和编号不在本次规划中修改，后续打包仍遵守发布流程。

当前推荐入口已有部分依赖与硬件检查；完整 Shader 库、旧预设和手动滤镜入口尚未统一接入。本节保留为规划要求，模型与推理运行库最终可用性仍由后台准备验证。

## 名称与状态规则

- 子页面使用「超分」「补帧」「降噪与去色带」的对应标题，顶部显示当前方案。
- 开关用复选标记；互斥方案用单选标记；执行动作使用明确动词。
- AI 显示「未安装、硬件不支持、未准备、准备中、可用、失败」；仅准备中显示取消，准备结束不自动启用。
- 不可用方案置灰并显示理由，保留发现入口；无需把插件名和硬件参数堆在正常选项标题中。
- 不同关闭／恢复动作明确范围：关闭推荐增强、清空全部 Shader（含手动项）、清空全部视频滤镜、恢复画面布局、恢复调色。不能统一叫「恢复原始」。
- 清空手动处理放在当前处理管理页，明确操作范围。关闭推荐增强保持不会清除外部脚本拥有的处理项。
- 原生统计显示 CPU/GPU／帧耗时；处理状态显示增强、Shader、色彩与准备状态，二者保持各自用途。
- 常用入口尽量两次到达，普通设置不超过三级；完整 Shader 算法库可到四级。

### 调查依据

- mpv 官方分别使用 glsl-shaders 管理用户渲染着色器、vf 管理视频滤镜链；VapourSynth 是 vf 的一种后端。https://mpv.io/manual/master/#video-filters 及 https://mpv.io/manual/master/#options-glsl-shaders
- PlayKit 的 GLSL 与 K7sfunc 文档独立介绍两类处理，不能将「AI」与「VS」划等号；例如神经网络 Shader 同样归着色器。https://github.com/hooke007/mpv_PlayKit/wiki/4_GLSL 及 https://github.com/hooke007/mpv_PlayKit/wiki/3_K7sfunc

### 推荐层级（待用户确认）

一级按处理体系，二级按用途，三级是可执行方案／文件；完整库允许多一层算法目录。不要把全部 34 个算法族直接铺满二级，也不要在日常页展开两套完整索引。

```text
着色器
├─ 常用整套方案 → 通用／动画的少量完整预设
├─ 通用超分 → FSRCNNX、RAVU、FSR 的精选单项
├─ 动画超分 → ArtCNN、CuNNy、Anime4K 的精选单项
├─ 锐化 → CAS、Adaptive Sharpen、RCAS
├─ 降噪与去色带 → 对应 Shader 单项
├─ 色度重建 → KrigBilateral、CfL
├─ 完整算法库 → 原 34 类目录 → 全部文件
└─ 当前处理链 → 启停／移除／排序说明／清空本类

视频滤镜
├─ 超分 → DirectML、MIGraphX、TensorRT 等具体方案
├─ 补帧 → MVTools、RIFE 等具体方案及后端
├─ 降噪 → CCD、BM3D 等方案
├─ 片源修复 → 去隔行、去块、帧率／源标记修复
├─ 组合方案 → 少量已验证的滤镜组合
└─ 当前滤镜链 → 状态／准备／取消／移除／清空本类
```

以上只是目标分类，具体收录项必须与本地文件、插件、模型与验证结果匹配；示例算法并不等于当前全部可用。

### 操作边界

- 单项用开关并追加／移除本项，便于自由搭配；整套预设是切换本类组合，必须标清作用范围，不能点击后悄悄清空另一类。
- 视频滤镜系统默认每类一个方案，允许降噪、超分、补帧组合；Shader 可与其组合，但双重超分／锐化提示重复处理，不把「可组合」等同于任意搭配有效。
- 当前处理页显示实际链、拥有者、位深与色彩限制、准备状态。Shader 列表次序与实际 HOOK 执行次序要区分；不同阶段不能通过上下移动改变。
- 软件／模型缺失、硬件不支持、准备中／失败／可用分别显示；NVIDIA 专用后端按硬件检查，不按带 NV／AMD 的 Shader 名字粗略判断。
- 去色带 deband 与轻量时间插值 interpolation 是渲染器选项，不冒充 GLSL 文件或 VS 滤镜；建议放「画面 → 渲染处理」／「视频 → 播放同步」并明确说明。色彩目标、ICC、HDR 映射仍放画面。

### 来源与选择依据

- [Anime4K 官方 Windows 配置](https://github.com/bloc97/Anime4K/blob/master/md/GLSL_Instructions_Windows_MPV.md)提供 Fast／HQ 完整组合；本地原有十二组保留其顺序。A／B／C 按片源退化类型选择，不能当成低／中／高画质排名。[高级说明](https://github.com/bloc97/Anime4K/blob/master/md/GLSL_Instructions_Advanced.md)要求 A+A／B+B／C+A 仅用于至少 2× 放大，本地精选入口检查实际显示倍率。
- [ArtCNN 作者说明](https://github.com/Artoriuz/ArtCNN)将 C4F16 定位为轻量实时模型，C4F32 取决于硬件能力。本轮选中性模型，未把 DS／DN 的附加处理混入推荐超分。
- [Artoriuz 的公开重采样评测](https://artoriuz.github.io/blog/mpv_upscaling.html)是特定测试方法下的比较，不构成所有视频的统一排名。FSRCNNX 8 保留为通用候选；不照搬旧的「色度重建＋超分＋锐化」万能组合。

三个档位是本项目按用户指定桌面型号设定的手动选择参考，属于规划判断，**不是上游实测映射或本机性能保证**。3050 以下硬件可先用原始播放；分辨率、放大倍率、帧率、显存容量、驱动与 Shader 编译均影响负载。高档用户也可选低档；不能仅因型号较新就开放 TensorRT／CUDA 等 AI 后端。5060 Ti 的 8／16 GB 型号对 AI 的显存约束不同。

24／30／60 fps 每帧分别约有 41.7／33.3／16.7 ms；预设应以实际播放掉帧和渲染耗时为准。增强默认关闭，选择仅对当前文件生效；精选入口暂阻止未经验证的 HDR／广色域素材路径。高级手动库仍供用户自行选择，不宣称其色彩保真已验证。
