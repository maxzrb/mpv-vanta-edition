# VS Renderer-Player 与 mpv 同步策略对照

日期：2026-10-04。对象为用户提供的 VS Renderer-Player 1.0.4 便携目录；同一 LG 8K AV1 HDR10 59.94fps 素材。结论针对包文档、设置和独立解码／mpv 实验，不冒充 VS GUI 的真实呈现测量。

## 已确认的差异

随包 DEPENDENCIES.md 说明其使用打过补丁的 3FP，构建基点标为 ee2bfde51a8f85ac156a2253845d5dcb4a07df09，API 14；不应当作前轮 9 月 30 日标准 3FP 发行版。请求取得该提交源码未成功，因此未将其他提交的调度阈值当作本包实际行为。根目录还包含另一构建的 FFmpeg、LAV、madVR 与 VS 插件。

读取现有 player.ini：core=3FP、decode/video=3FP、decode/audio=3FP、speed=1、predecode=true、frames=8、multithread=true。renderer=VS 不证明每个文件都正在执行 VS；随包 player-direct-open-1.0.4.md 说明无预设原画和固定直通走原生 3FP，不建立 VS 源。

随包 realtime-bridge.md 描述增强模式的调度：单一左路时钟；处理帧请求不重叠，完成后选择当前最新目标，跳过中间落后帧。player-performance-1.0.2.md 与 player-six-stage-1.0.3.md 描述稳定观察后逐级降载，最终到 Jinc／D3D11 原生或 Bilinear 回退。该策略只解释适用的增强／自动档，不能直接套用到原画 8K 播放。

预解码和队列可减少起播／短暂抖动，长期处理速度不足时队列仍会耗尽。不同迟到容忍、帧选择和 Present 节奏可能使较低实际帧率看起来更均匀，但需以唯一源帧数与帧间隔证明；单凭 Present 次数可能包含重复帧。

## 同一片源的实验

VS 包根目录 FFmpeg：D3D11VA、GPU 帧输出 null，20 秒处 300 帧。末段差分约 45.2fps，与前轮工具的 45.3fps 接近，未见这两个 CLI 构建实现实时 59.94fps。总运行包含精确快进预解码，不直接按总耗时计算稳定吞吐。这个结果不是 VS GUI 的实际解码／呈现帧率，不能排除 GUI 的队列与解码参数差异。

mpv 使用当前配置、禁脚本，启动等待 10 秒再采样；静音 ao=null，故内部同步偏差不等于实测听感音画偏差。framedrop=no 组墙钟 10.10 秒、素材推进 7.56 秒、VO 丢帧计数零，结束 avsync 约 3.59 秒。它证明减少丢帧计数可伴随视频进度落后，不能作为完整 60fps 的成绩。

发现自动 8k-fix 配置会设置 video-sync=audio，覆盖启动参数的 display-resample。因此首轮“显示同步”组实际仍是 audio，明确不算有效显示同步对照。后续在视频加载后通过 IPC 改成 display-resample，再核查实际属性与结果，数据为 mpv-display-results.json。有效组为 display-resample，当前显示刷新率报告 165Hz；墙钟 10.89 秒、素材推进 8.84 秒、VO 丢帧增加 502，仍未解决吞吐不足。165Hz 与 59.94fps 的节奏、实际 VRR 状态也需分别核查，不能假设当前显示为 60Hz。该单次短测试不证明稳定观感改进比例。

原始证据位于忽略目录 tmp/modernization/vs-player-audit/；源播放器目录只读，没有启动 VS GUI 或修改其 INI，未改 mpv 活动配置。相关基础数据见 [8K 掉帧排查](8K-AV1掉帧排查.md)。

## 对本项目的改进方向

先拆开 8K 硬解选择和同步选择：原配置的“硬解修复”不应无条件强制音频同步。尚未修改该配置，下一轮应以实际生效属性对比 audio、display-resample 与帧丢弃策略，检查正常片源与过载片源。

持续吞吐不足时保持实时、音画同步与保留每一帧无法同时满足。推荐处理是清楚报告过载，提供用户选择的轻量路线或更低解码负载素材；不默认关闭 framedrop，不用变慢掩盖不足，不把自动降低画质悄悄称为同等质量优化。

比较 GUI 下一步需采集相同片段的媒体时钟推进、实际解码模式、唯一源帧呈现数／跳过数、队列深度、帧间隔分布和音频位置，并包含起播、稳定播放、seek 三类场景。确认有无补帧和自动降载，再判断视觉优势来自节奏、缓冲、降载还是不同后端。当前不能断言 VS GUI 已经完整播放了该视频的 60fps，或断言其顺滑必然靠音画不同步。

同步选项依据：[mpv 官方手册](https://mpv.io/manual/master/#options-video-sync)。显示同步用于匹配刷新率和播放节奏，不能凭空补足解码吞吐。

色彩实施阶段已移除 8k-fix 的 `video-sync=audio`，不再强制覆盖用户同步策略；保留 auto-safe 硬解。原实验数据保持为当时配置证据，不把该修改解读为解码吞吐提高。
