# ACM 起播闪烁与后台窗口修复

检查与修复：2026-10-13 17:58，Asia/Shanghai。源码基线 `cc67ad9`，当前正式版本仍为 v1.6.1。

## 触发点与复现

本机保存的主模式为 HQ，Windows 显示模式为 SDR ACM／WCG。正式起播日志显示：

- 0.062 秒：显示器信息未就绪，先应用 SDR sRGB 目标。
- 0.162 秒：创建第一条 D3D11 输出；0.248 秒前台脚本处理第一次窗口。
- 0.280 秒：原生检测识别到 WCG；0.396 秒暂存视频轨为 `vid=no`。
- 0.431 秒：切换到 FP16／线性输出；0.461 秒销毁旧窗口，0.477 秒重新初始化输出。
- 原前台脚本已消耗首次抬升请求，不处理第二个窗口，因而可能在后台继续播放。

用完整隔离配置及测试自有遮挡窗口复现相同链路。旧版确实创建两个窗口，最终播放器处于遮挡窗口之后；不是仅凭日志猜测。原日志和修改前文件保留在本地忽略目录 `backup/startup-acm-flicker-20261013/`，不进入仓库或公开包。

## 修改

1. `display-color-native.lua` 复用既有 DisplayConfig 查询，增加窗口创建前的主屏、指定屏及明确绝对位置预查。真实窗口建立后继续按 HWND 校验；未修改 Windows 显示设置。百分比位置及缺省尺寸不宣称与任意多屏布局完全等价；跨屏全屏保持未知回退。
2. `color-target.lua` 在初始输出选择时使用预查结果，窗口记忆写入启动位置后、视频预加载钩子结束前重新匹配。HQ／ACM 第一次就创建 FP16/scRGB 输出。窗口 ID 先到、显示脚本状态后到时，按真实 HWND 同步确认，避免把通知空档误判为 ACM 关闭。
3. `window-foreground.lua` 在主动起播已有两秒期限内，若窗口身份变化则补抬升新窗口；不延长期限。自动切集、暂停、退出不续期，不把用户的置顶偏好改为开启。
4. 新增 `tools/test-startup-acm-window.py`：完整隔离配置、真实视频进度、窗口身份记录、GPU 上下文数量和原生显示层级检查；支持旧版复现、仅前台修复、启动页到媒体及双后端。
