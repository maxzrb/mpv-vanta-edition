# 源色彩与滤镜精度优化结果（2026-10-07）

本轮按用户明确要求，以标准数学、正确源信息和软件像素回归作为验收基础，不以取得专业测量设备为完成条件。增强按模型与后端实际支持格式运行，兼顾视觉效果、兼容性和播放负载；不统一强制 16bit 或改变模型推理精度。

## 已应用的修正

1. **源矩阵与范围**：修正本机 K7sfunc 1.8.1 中 RIFE／DRBA、AI 超分、CCD／DPIR 等 RGB 转换。读取现代 `_Matrix`，缺失时读取 mpv 桥接的 `_ColorSpace`；按同一源矩阵转入模型、转回 YUV，明确保留 full／limited 范围。未标记源沿用合理的分辨率推断。没有强行把源传递函数或原色改成 BT.709。
2. **通用格式层**：解除旧白名单造成的整数 YUV 12／16bit 与 4:4:4 降格式。`FMT_CTRL(fmt_pix=0)` 保留可桥接格式；用户明确锁定 8bit 的选项仍有效。SVP 的 8bit 分析、8／10bit 主图像策略和模型 RGBH／RGBS、FP16／FP32 IO 保持各自语义。
3. **真实末帧时长**：完整配置的短片测试复现 `No PTS after filter`，CCD 单独启用也会发生，不能只归因于 RIFE。源时长缺失或为负时按已知帧率回退；正常逐帧时长不改，保留 VFR，桥接 0/1 EOF 占位帧也不改。RIFE 输出按原有倍率计算必要回退，不强制重写正常时长。
4. **维护可复现**：运行库改动保存在 [K7 补丁配方](../../portable_config/vs/patches/k7sfunc-1.8.1-color.json)，保留上游 GPL 许可。手动维护工具刷新对应组件摘要并留存原件；正常起播、菜单和滤镜选择不调用维护工具。原有一键启用、组合、失败回退和菜单位置保留。

VapourSynth 官方说明输入帧属性优先于 `matrix_in` 等默认参数，因此修复不能仅删除旧 709 参数或仅修改最后显示的标签；输出转换也必须选择正确源矩阵。[Resize 文档](https://www.vapoursynth.com/doc/functions/video/resize.html)

完整配置 5 类 GPU 色块相对独立矩阵／sRGB／线性原色转换参考的最大 16bit 码值误差依次为 **38、1、1、110、98**，均在本回归阈值 128 内；CCD 静态色块结果相同。参考先以实际量化 YUV 值计算，再转换到目标 sRGB。输入夹具声明编码前后的范围，并先逐字节解码回读，避免生成工具改变范围而误归因于播放器。

普通 gpu-next 的浮点缓冲与 SDR／scRGB／PQ 色彩目标策略沿用既有实现。本轮没有更换缩放档位、开启额外对比度恢复、修改系统 HDR 或推广新的性能默认；因此上述稳态采样是兼容性验证，不宣称获得新的性能收益，也不将短片每次重新加载模型的耗时计为稳态性能。

## 验收边界与后续范围

- 本轮软件验收完成后即可使用，不要求用户购买仪器、先完成屏幕校准或解锁滤镜。
- 标准目标、源矩阵／范围正确和足够缓冲精度，仍不等同于屏幕实际色差为零。面板、驱动／系统显示信息不准确时只能采用可信信息或明确的标准基线。真实测量作为将来的可选补充。
- AI 模型会改变像素和观感；静态色块通过不表示所有动态场景均严格保持原片，也不把模型效果当作转换错误。HDR 模型的主观效果仍由用户实际选择判断，不额外设置认证门禁。
- 数值回归覆盖常见 BT.601／709／BT.2020 NCL，未宣称覆盖每种罕见矩阵和每个设备。NVIDIA／Intel 实机、完整 DV 及 3FPlayer 同条件运行对照保持未执行，不阻止这轮已验证软件修正。
- 2 秒短片反复循环会重新初始化模型，仍有加载开销；已验证链路保持与错误修复，不承诺短片循环无缝。8K SVP 按用户要求不纳入验收。
- 原有可选 CUDA BM3D 依赖加载错误 126 未由本轮引入；本机 DML／CCD 测试不使用该 CUDA 后端。
