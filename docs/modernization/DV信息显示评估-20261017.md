## 2026-10-17 有限后台读取验证

### 已实现的研究原型

- 独立Lua脚本只在首个`playback-restart`之后延迟500ms启动异步子进程，不在`on_load`、解码初始化或首帧前等待探测；每次载入仅一次，跳转不重复启动。
- Python后台最多读取本地文件片头1MiB一次，将该内存前缀送入随包FFmpeg；最多检查前两路视频、每路前8包，HEVC转Annex B后仅保留类型62 NAL。流拷贝，不解码，不增添运行时。
- FFmpeg只能看到有限管道输入，无法继续扫描原片；每个FFmpeg限时1秒，Lua整个后台任务3秒预算。换片／退出取消请求，代号隔离迟到结果，超时后的回调不能覆盖终态。
- URL、UNC和映射网络盘在stat/open之前排除。缺失、截断、损坏、超预算或不支持语法均保留未知；本次未实现持久化缓存及正式信息界面。
- RPU解析按固定版本[libdovi头部](https://github.com/quietvoid/dovi_tool/blob/614c816b6446dcd1dbaf433403d499a6026fbb5a/dolby_vision/src/rpu/rpu_data_header.rs)、映射及[NLQ分类](https://github.com/quietvoid/dovi_tool/blob/614c816b6446dcd1dbaf433403d499a6026fbb5a/dolby_vision/src/rpu/rpu_data_nlq.rs)核对，验证CRC-32/MPEG-2、支持的头部及NLQ字段，不用Profile 7或disable_residual_flag单独猜MEL／FEL。它不是完整DV语法验证器。

### 实测结果

| 项目 | 结果 |
|---|---|
| 实际片源 | 本机`DOLBY_VISION_CES/00025.MKV`，实际MPEG-TS双层结构 |
| 最小测试前缀 | 256KiB提取8个RPU，约62ms；它不是对所有文件的最低保证 |
| 原型预算 | 1MiB；自动先查基础视频再查第二路，观察到8个CRC有效RPU一致为P7／FEL |
| 完整配置起播对照 | 4轮交替，共8次；未启用中位484ms，启用中位464ms，时间从同一Lua脚本载入测到首个playback-restart |
| 后台启动时点 | 首帧后500.1–501.3ms |
| 后台总耗时 | 218–239ms，含Python启动、读入、两次FFmpeg与解析；内部工作139–147ms |
| 播放状态 | 8次均视频时钟推进，decoder/VO丢帧计数0，无缓存等待 |
| 正反例 | 上游7个MEL／FEL／P8小样预期匹配；逐字节截断和CRC位损坏均拒绝可靠分类 |
| 封装夹具 | 同一含RPU轨道重封装为MKV和faststart MP4，有限读取均识别FEL；不是独立影片验证 |
| 取消／超时 | 任务运行中换到SDR片源，不接收旧片结果；将时间预算缩为10ms后稳定保留timeout，播放继续 |
| 未知状态 | SDR、缺失文件、URL及UNC均保持未知；不标记“无RPU” |

起播样本未观察到新增等待，但未启用组含一次850ms初次启动；两组范围也有波动，不能把20ms中位差宣传为加速。首个playback-restart是核心可呈现画面的事件代理，不是外部高速摄像测量。此轮只验证本机D3D11、一段实际双层DV影片和小型夹具，不等于机械盘、全部封装、其他DV Profile和全部渲染后端均认证。

### 接入建议与仍需完成的工作

可采用此方案实现片源信息：先显示现有DV标签，首帧约0.7秒后有证据再补充MEL／FEL与RPU。容器／流组证据另行决定BL／EL存在关系，不能仅凭两个视频轨道猜双层关联，也不能把码流类型写成“FEL已应用”。

正式接入时复用media-format-info统一结果，将统计页和底栏去重；只对已识别DV的本地文件安排任务，按规范路径、大小、mtime及探测版本缓存，缓存命中不再起进程。片头无moov、RPU晚出现、需要前序映射或不支持语法时停止并保持未知，不自动全片扫描。缓存、正式触发筛选、BL/EL关联证据及UI尚未实现；当前只有研究原型。

原型及原始证据位于本地`tmp/dv-info-20261017`，不进公开包；汇总已固化为`docs/modernization/DV后台有限读取验证-20261017.json`。未修改活动播放配置、未升级核心、未发布v1.6.3。
