## 本轮功能

- 起播／关闭黑闪：force-window=yes，色彩脚本退出只取消任务；窗口记忆保存边框偏移，并在首次创建前一次恢复位置／大小。
- 起播减负：OSD 字体改用 fonts/osd，字幕保留完整字体；文件浏览器使用 Windows GetLogicalDrives，省去同步 fsutil。
- GPU 面板：DXGI／驱动标志过滤虚拟显卡，显示真实名称与本播放器／整机占用；最忙引擎口径。原生及兼容查询都沿用同一身份过滤。
- 面板：按实际 ASS 边界自适应，缓存布局；宽窗口将 CPU／GPU 区域由四行压为两行，窄窗口拆行；整体字号 20→24。

本轮七个既有配置／Lua 文件和新 gpu-adapters.lua 已整理；用户个人 window_state.conf 不上传，仍由脚本兼容迁移。

## 换机准备

1. 在具备完整播放器运行库的工作目录同步 master，保留自己的个人历史与运行状态。不要用当前机器缺失的开发目录去替换另一台完整环境。
2. Git 默认忽略 mpv／7z／Python／VS／Faster-Whisper／多数字体；只克隆源码不足以完整打包。需保持原有运行环境，或从正式 Base／Extras／Faster-Whisper 包按需补齐，再覆盖本轮源码。
3. 在项目根执行下列准备命令，从 fonts/ 的七个原始字体生成相同的 fonts/osd/：

```powershell
.\tools\prepare-osd-fonts.ps1
.\tools\prepare-osd-fonts.ps1 -VerifyOnly
```

也可用 `-FontProjectRoot '播放器目录'` 指定运行环境。脚本先检查全部源字体 SHA-256，再原样复制；来源不齐或版本不同会停止，不生成不完整的新目录。字体生成清单在 tools/osd-fonts-manifest.json，目标副本继续被 .gitignore 忽略。复用已有字体的原始版权／授权，不添加或改变授权。

4. 本轮 mpv.conf 依赖新 OSD 子目录。01 包会收入生成后的字体，04 会排除 fonts，因此本轮功能更新应同时提供 01／04；单独更新 04 给没有该目录的旧安装可能缺字体或图标。
5. 用户确定新版本后，完整读取根发布流程.md，先处理下方审计事项，再开始构建。流程修订权仍归项目所有者；本轮没有修改该文件或打包脚本。

## 打包／发布审计结论

六个脚本语法通过，包名、01→04 顺序和安装器识别基本匹配；以下事项需要发布前处理：

- 01 的 Set-Content -Encoding UTF8 -NoNewline 在 Windows PowerShell 5.1 写 BOM，违反无 BOM 铁律；PowerShell 7 不带 BOM。脚本应显式使用 UTF8Encoding(false)，并核验包内及本地版本标记。
- 发布流程称 03 超过 1900MB 自动分卷，但脚本没有分卷参数；上传清单也固定写 02 两卷，需要按最终决定和实际产物统一。
- 04 排除 fonts／licenses，但 README 称包含字体；需明确本轮 fonts/osd 由 01 交付。
- 03／04／私包独立构建后不清理暂存目录，仅总入口清理 build；04 没有与 01／02 相同的生成文件清理。独立复用路径需补足门禁／收尾。
- 私包找不到安装器仅警告并继续，流程要求必须包含安装器。
- 01 多个必需输入缺失会跳过，需检查核心和全功能依赖清单。README 私包合并规则过时；流程 Release Note 结构化信息条款存在文字冲突。
