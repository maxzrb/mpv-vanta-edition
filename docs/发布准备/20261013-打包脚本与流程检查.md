## 不一致与缺口

### 1. 版本标记在 Windows PowerShell 5.1 下会带 BOM（高）

[build-01-base.ps1:156](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/build-01-base.ps1#L156) 使用 Set-Content -Encoding UTF8 -NoNewline。流程第 2、4.1、5 节要求 UTF-8 无 BOM、无换行。实测同一写法：Windows PowerShell 5.1.26100.9549 产生 EF-BB-BF-31-2E-32-2E-33；PowerShell 7.6.6 产生 31-2E-32-2E-33。流程没有限定必须使用 PowerShell 7，因此不能依赖调用环境。

建议脚本明确使用 UTF8Encoding(false) 的 WriteAllText，并增加逐字节核验。两个编码样本保存在本目录，仅测试字符串 1.2.3，不是发布定号。另一个步骤缺口：01 只写暂存标记，不更新播放器根目录的本地副本；流程第 5 要求本地副本同步，需要明确由谁、何时同步。

### 2. 03 的自动分卷描述与脚本不符（高，超过限制时触发）

[发布流程.md:124](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/发布流程.md#L124) 声明 03 超过 1900MB 自动分卷，但 [build-03-fasterwhisper.ps1:92](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/build-03-fasterwhisper.ps1#L92) 没有 -v1900m，始终生成单个 .7z。02 则始终使用 -v1900m（归档较小时可能只有 .001，较大时可有任意多个分卷）。发布上传清单仍固定写“02 两个分卷”及单个 03，不能通用覆盖脚本可能产生的分卷数量。

建议由项目所有者决定 03 是否支持分卷，并让上传／镜像清单按实际产物枚举。安装器扫描器本身已支持编号包的任意连续三位分卷。

### 3. 04 排除字体及许可证，但 README 称包含字体（中；本轮配置单更有实际依赖）

[build-04-config.ps1:38](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/build-04-config.ps1#L38) 删除 fonts 和 licenses；脚本生成的 README-Config包.txt 与根 README 仍称 04 包含字体／个人配置单独更新只需 04。当前发布流程只特别写了 04 不含 Logo 素材，未明确字体和许可证边界。

本轮播放器起播优化将 osd-fonts-dir 改为 ~~／fonts/osd，并新增七个字体副本。01 的全量配置复制会包含它们，但 04 会删掉整棵 fonts；如果旧安装没有这个子目录，单独更新 04 不能满足新配置的字体依赖，可能发生字体回退或图标缺失。本轮发布至少需要同时更新 01，或由所有者确定新的资源交付边界。

### 4. 独立子包构建的清理规则不足（中）

流程第 5 写“脚本会自动删除 build/”，但 03、04、私包脚本结束后都保留各自暂存目录；01／02 只删自身目录，只有总入口最终删除 build/。流程 4.1.1 又允许单独重建子包，所以原样复用路径不能依赖总入口清理。

[build-04-config.ps1:71](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/build-04-config.ps1#L71) 的 04 清理只删除缓存目录，不像 01／02 那样删除 .pyc/.log/.tmp 等生成文件，也没有统一的禁入目录校验。此处是控制缺口，未发现当前活动输入中被 04 保留的日志实际泄漏；本地 files/ 下日志会随整个 files 目录排除。建议统一“清理＋校验”并明确独立调用的收尾职责。

### 5. 私包缺安装器仍能生成（中）

[build-full-private.ps1:109](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/build-full-private.ps1#L109) 在找不到安装器候选时仅警告后继续压缩；流程第 4.2、5 要求私包必须包含 release/ 中最新版安装器，哈希一致。建议构建缺必需安装器时失败，或由所有者明确允许无安装器私包；当前流程没有这项豁免。

### 6. 核心／运行时缺失大多被静默跳过（发布前置缺口）

[build-01-base.ps1:161](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/build-01-base.ps1#L161) 与多个 Copy-IfExists／Invoke-CopyTo 会跳过缺失输入；01 仅强制检查 7z 和 README，缺 mpv.exe 也可能生成无播放器的归档。流程允许 ffmpeg 缺失时跳过并人工确认，其他核心运行时同样需要发布前输入清单和产物核验。新克隆不包含 Git 忽略的 mpv、7z、VS、Python、字体等运行支持，因此不能把“源码克隆完成”当成可直接完整构建。

建议维护必需／可选输入清单，强制检查核心及功能依赖；本次没有启动正式构建。

### 7. README 和发布说明规则存在文字冲突（低）

根 README 称私包合并 01～04 全部公开包，实际脚本及发布流程不合并 03。[发布流程.md:169](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/发布流程.md#L169) 要求安装顺序／校验和／安装器说明不放 Release Note，而 [发布流程.md:170](https://github.com/maxzrb/mpv-vanta-edition/blob/cdc90c9714ae0e65848f4e9971216a4887c2f813/发布流程.md#L170) 又允许这些信息另置其后。需要所有者统一口径；流程修订权归所有者，本次没有改写。

## 本轮本地修改覆盖核验

local-remote-comparison.json 保存了七个既有文件的 SHA-256 对照：mpv.conf、color-target.lua、window-size-position.lua、stats.lua、stats.conf、system_metrics.lua、winroot.lua 均与远端不同。新增 gpu-adapters.lua 和 fonts/osd 七个字体副本在远端提交中不存在；远端 .gitignore 默认忽略非既定字体及 fonts/osd。

因此直接用当前远端构建，会遗漏本轮黑闪修复、起播减负和 GPU 面板调整。将变更整理到发布源码后，01／04 的配置复制范围可以覆盖 Lua 新模块；字体新资源仅进入 01。还需要审阅本地改动、落实忽略资源输入，并按流程做包内清单和实际播放验收。本次拉取没有覆盖本地文件，也没有把本地改动推送到远端。
